== Qu'est-ce que le dossier professionnel ?

Le dossier professionnel (DP) est un document obligatoire pour valider le titre de **Concepteur Développeur d'Applications (CDA)**. Il documente vos compétences professionnelles à travers des exemples concrets tirés de vos expériences en formation ou en entreprise.

[NOTE.speaker]
====
Le DP pour le titre CDA se concentre sur des compétences spécifiques :
1. **Concevoir et développer des applications**.
2. **Créer des bases de données performantes**.
3. **Mettre en œuvre des méthodologies de gestion de projet**.

Le DP est crucial pour :
- Montrer votre capacité à mettre en œuvre des projets réels.
- Démontrer la maîtrise des compétences techniques.
- Préparer efficacement votre soutenance devant le jury.
====

== Importance du dossier professionnel

### Pourquoi le DP est-il essentiel ?
1. **50% de l'évaluation** du titre repose sur le DP.
2. Il est le **point central de la soutenance orale**.
3. Il reflète votre capacité à analyser et expliquer vos projets.

[NOTE.speaker]
====
En plus de valider vos compétences, le DP est un document qui peut être présenté à des recruteurs pour valoriser votre parcours. 
Conseil : Rédigez-le de manière claire, structurée, et professionnelle.
====

== Structure du dossier professionnel

Le DP pour le titre CDA comporte généralement les parties suivantes :
1. **Introduction** : Contexte et présentation du candidat.
2. **Activités professionnelles** : Description des projets réalisés.
3. **Compétences mobilisées** : Analyse des compétences utilisées.
4. **Analyse critique** : Retour sur les points forts et les axes d'amélioration.

=== Exemple de structure détaillée

[source,text]
----
1. Introduction
   - Contexte général.
   - Objectif du dossier.

2. Activités professionnelles
   - Projet 1 : Création d'une application de gestion d'inventaire.
   - Projet 2 : Développement d'une API REST pour une application mobile.

3. Compétences mobilisées
   - Compétences techniques (ex. : programmation en Java, gestion des bases de données SQL).
   - Méthodes appliquées (ex. : architecture MVC, Agile/Scrum).

4. Analyse critique
   - Bilan des projets réalisés.
   - Propositions pour améliorer votre méthodologie.
----

[NOTE.speaker]
====
Astuce pour organiser votre DP :
- Suivez une structure claire et logique.
- Utilisez des exemples concrets pour illustrer vos compétences.
====

== Rédiger chaque partie du DP

=== 1. Introduction

*Présentez votre parcours et vos objectifs.*  
Exemple :  
[source,text]
----
Je m'appelle Julien Martin, passionné par le développement logiciel. Ce dossier professionnel illustre mes compétences acquises durant ma formation CDA et mes expériences professionnelles. À travers deux projets principaux, je démontrerai ma capacité à concevoir et développer des solutions logicielles adaptées aux besoins des utilisateurs.
----

[NOTE.speaker]
====
L'introduction doit capter l'attention. Soyez professionnel et clair :
- Indiquez pourquoi vous avez choisi ce domaine.
- Mettez en avant vos objectifs pour le DP.
====

=== 2. Activités professionnelles

*Décrivez vos projets en détail.*  
Exemple pour un projet de gestion d'inventaire :  
[source,text]
----
Projet : Développement d'une application de gestion d'inventaire pour une PME.

Objectif : Permettre à l'entreprise de gérer son stock en temps réel, d'émettre des alertes en cas de rupture de stock, et de générer des rapports mensuels.

Compétences mobilisées :
- Conception de la base de données MySQL.
- Développement du back-end en Java avec le framework Spring Boot.
- Création d'une interface utilisateur en React.

Résultat : Réduction de 20% des erreurs de gestion de stock et gain de temps de 15% pour les équipes logistiques.
----

[NOTE.speaker]
====
Lorsque vous décrivez un projet :
1. **Donnez le contexte** : Pourquoi ce projet a-t-il été réalisé ?
2. **Expliquez votre rôle** : Quels étaient vos responsabilités et vos contributions ?
3. **Mettez en avant les résultats mesurables**.
====

=== 3. Compétences mobilisées

*Analysez les compétences techniques et méthodologiques utilisées.*  
Exemple :  
[source,text]
----
Pour le projet de gestion d'inventaire, j'ai mobilisé les compétences suivantes :
1. Développement Java : Implémentation d'une architecture MVC.
2. Gestion des bases de données : Optimisation des requêtes SQL pour améliorer la vitesse de traitement.
3. Méthodes agiles : Planification des sprints et gestion des user stories via Jira.
----

[NOTE.speaker]
====
Les compétences mobilisées doivent être directement liées aux référentiels du titre CDA :
- Techniques (ex. : programmation, gestion de bases de données).
- Méthodologiques (ex. : gestion de projet Agile, rédaction de documentation technique).
====

=== 4. Analyse critique

*Faites un bilan objectif des projets réalisés.*  
Exemple :  
[source,text]
----
Points forts :
- L'architecture modulaire utilisée a permis une évolutivité facile de l'application.
- Les feedbacks utilisateurs ont confirmé une interface intuitive et ergonomique.

Axes d'amélioration :
- Une meilleure gestion des priorités aurait réduit le temps de développement.
- Une formation complémentaire sur Docker aurait optimisé le déploiement.
----

[NOTE.speaker]
====
Soyez honnête dans votre analyse critique :
- Mettez en avant vos réussites mais reconnaissez vos erreurs.
- Proposez des solutions pour pallier les lacunes identifiées.
====

== Conseils pratiques pour la rédaction

1. Commencez tôt : Documentez vos projets dès leur réalisation.
2. Relisez régulièrement : Faites corriger votre DP par des pairs ou des formateurs.
3. Organisez-vous : Utilisez des outils comme des tableaux ou des checklist pour suivre vos compétences couvertes.

[NOTE.speaker]
====
Le DP est un projet à part entière. Prenez-le au sérieux et consacrez-y du temps régulièrement.
====

== Conclusion et préparation à la soutenance

Le DP est un outil clé pour réussir votre titre CDA. Une rédaction bien pensée et une soutenance préparée vous permettront de mettre toutes les chances de votre côté.

[NOTE.speaker]
====
Pour la soutenance :
- Préparez une présentation concise de vos projets (5-10 minutes).
- Entraînez-vous à répondre aux questions du jury sur vos choix techniques et méthodologiques.
====
