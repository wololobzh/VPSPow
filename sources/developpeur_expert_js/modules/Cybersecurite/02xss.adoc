== Introduction aux failles XSS

Les failles XSS (Cross-Site Scripting) permettent à un attaquant d’injecter du code malveillant dans une application web. Ce code est ensuite exécuté par le navigateur des utilisateurs, ce qui peut entraîner des vols de données, des modifications de contenu, et bien d'autres attaques.

Les failles XSS sont dangereuses car elles peuvent être exploitées pour exécuter des scripts malveillants dans le contexte d’un site web de confiance.

[NOTE.speaker]
====
Les failles XSS exploitent la possibilité d’injecter et d'exécuter des scripts malveillants dans une application web, en particulier dans des entrées utilisateurs non sécurisées.
====

== Types de failles XSS

Il existe plusieurs types de XSS, chacun ayant ses propres mécanismes et vecteurs d'attaque.

=== XSS stockée (Stored XSS)

Dans une attaque XSS stockée, le code malveillant est **stocké** directement dans la base de données de l'application (ex. : dans un commentaire, un profil utilisateur, etc.). Lorsque les autres utilisateurs consultent la page où se trouve le script malveillant, celui-ci s’exécute automatiquement dans leur navigateur.

**Exemple** : Un utilisateur publie un commentaire contenant du code JavaScript malveillant. À chaque fois que quelqu’un visualise le commentaire, le script s’exécute.

=== XSS réfléchie (Reflected XSS)

Dans une attaque XSS réfléchie, le code malveillant est **réinjecté** dans la réponse d’une requête HTTP. Cela se produit souvent lorsque l'application inclut des données non sécurisées directement dans une page.

**Exemple** : Un attaquant envoie un lien contenant du code malveillant à un utilisateur. Lorsque l’utilisateur clique sur le lien, le code est exécuté dans son navigateur.

=== XSS basée sur le DOM (DOM-based XSS)

Une attaque XSS basée sur le DOM manipule directement le Document Object Model (DOM) de la page dans le navigateur. Cela se produit généralement côté client, sans qu’il soit nécessaire de modifier la réponse du serveur.

**Exemple** : Un site web lit des informations de l'URL et les insère dans la page sans filtrer les données, ce qui permet d’exécuter un script malveillant.

[NOTE.speaker]
====
Les trois types de XSS exploitent des faiblesses différentes dans la gestion des entrées utilisateur, mais toutes permettent l'exécution de scripts malveillants dans le navigateur de la victime.
====

== Impacts des failles XSS

Les conséquences d’une faille XSS peuvent être graves et inclure :

* **Vol de cookies et de sessions utilisateur** : Permettant à un attaquant de se faire passer pour la victime.
* **Détournement de navigation** : Redirige les utilisateurs vers des sites malveillants.
* **Modification de contenu** : Permet de manipuler l'apparence ou le contenu d'une page.
* **Enregistreur de frappes** : Enregistre les frappes de clavier de l'utilisateur pour voler des mots de passe ou des informations sensibles.

[NOTE.speaker]
====
Les attaques XSS exposent les utilisateurs à de nombreux risques, notamment le vol d'informations sensibles et l'accès non autorisé aux comptes.
====

== Prévention des failles XSS

Pour protéger une application contre les failles XSS, il est essentiel de suivre les meilleures pratiques de sécurité dans le traitement des entrées utilisateur.

1. **Échapper les caractères spéciaux** : Échapper les caractères comme `<`, `>`, `&`, et `'` avant de les inclure dans le HTML.
2. **Valider et assainir les entrées utilisateur** : Filtrer et valider toutes les entrées pour s’assurer qu'elles ne contiennent pas de code malveillant.
3. **Utiliser Content Security Policy (CSP)** : Mettre en place une politique de sécurité du contenu pour limiter les sources autorisées de scripts.
4. **Éviter l’injection directe dans le DOM** : Ne pas insérer des entrées utilisateur directement dans le DOM, surtout pour les URL et le JavaScript.
5. **Utiliser des bibliothèques sûres** : Utiliser des frameworks de rendu côté client qui neutralisent automatiquement les risques XSS, comme React ou Angular.

**Exemple de validation de données** :

[source,javascript]
----
function sanitizeInput(input) {
  return input.replace(/[<>&'"]/g, function (c) {
    return ({
      '<': '&lt;',
      '>': '&gt;',
      '&': '&amp;',
      "'": '&#39;',
      '"': '&quot;'
    })[c];
  });
}
----

[NOTE.speaker]
====
En suivant ces pratiques, les développeurs peuvent réduire considérablement le risque de XSS. Par exemple, une politique de sécurité du contenu (CSP) limite l'exécution de scripts à des sources de confiance.
====

== Outils pour détecter les failles XSS

Voici quelques outils pour détecter les failles XSS dans les applications web :

1. **OWASP ZAP (Zed Attack Proxy)** : Un outil open-source qui scanne les applications web à la recherche de failles de sécurité, dont les failles XSS.
2. **Burp Suite** : Fournit des fonctionnalités avancées de scan et de test pour détecter et exploiter les vulnérabilités XSS.
3. **SonarQube** : Outil d’analyse de code qui détecte les vulnérabilités XSS dans le code source.

Ces outils permettent d’automatiser la détection de failles XSS et de générer des rapports pour corriger les vulnérabilités identifiées.

[NOTE.speaker]
====
Les outils de scan comme OWASP ZAP et Burp Suite sont indispensables pour identifier les failles XSS. Ils facilitent le processus de sécurisation des applications.
====

== Conclusion

// tag::conclusion[]
* Les failles XSS exposent les utilisateurs à des risques de sécurité importants en permettant l'exécution de scripts malveillants.
* Il existe trois types principaux de failles XSS : stockée, réfléchie, et basée sur le DOM.
* La prévention des attaques XSS repose sur la validation des entrées, l’échappement des caractères spéciaux, et l’utilisation de politiques de sécurité de contenu.
* Les outils de scan comme OWASP ZAP et Burp Suite sont utiles pour détecter et corriger les failles XSS dans les applications web.
