== Api REST JSON : CRUD

Nous allons modifier les CRUD que nous avons fait dans un module précédent, afin de dire à NestJS de renvoyer uniquement du JSON, pour découpler les vues de notre serveur.

On verra aussi comment pourrait fonctionner l'authentification dans ce cas.

Nous avons adopté les principes RESTful, principes qui indiquent que nous devrions avoir 7 méthodes pour gérer nos ressources, on a déjà `index` et `store`, implémentons les suivantes :

[background-color=var(--r-oclock-color)]
== Create

Nous pouvons déjà créer des notes, on passe par un formulaire, car on a une application monolithique.

Dans le cadre d'une SPA (Single Page Application) ou plus simplement d'un front découplé de NestJS, on devra passer par la technique AJAX pour nos fonctionnalités.

On va voir dans ce module comment réaliser ces actions.

[background-color=var(--r-demonstration)]
=== Create : demo

Examinons d'abord les méthodes `index` dans `Notescontroller`, on a le décorateur `@Render` qui dit à NestJS de renvoyer une vue, il suffit d'enlever ce décorateur pour renvoyer les données en format JSON.

Au passage, on enlève (ou on commente) la méthode `create`, cette méthode ne sera plus utilisé dans le cadre d'une API REST JSON.

[source,typescript]
----
// notes.controller.ts
import { Controller, Get, Post, Body, Render } from '@nestjs/common';
@Get()
index() {
    return { notes: this.notesService.getNotes() };
}
----

== show

Afficher une ressource devrait être plus direct et plus simple, il y a juste deux particularités à prendre en compte : on récupère le paramètre d'URL avec un décorateur,

Et on convertit explicitement ce paramètre en nombre `(+id)` pour que typescript nous laisse tranquille :

[source ,typescript]
----
// notes.controller.ts
// * On paramètre la route avec l'id
@Get(':id')
// * On récupère l'ID avec un décorateur que l'on doit importer
async show(@Param('id') id: string): Promise<object> {
    // * Le + devant une string convertit celle-ci en nombre : '1' devient alors 1
    return { note: await this.notesService.find(+id) };
}
----

[background-color=var(--r-demonstration)]
=== show

On doit créer la méthode `find` dans le service et on fait appelle à https://sequelize.org/docs/v6/core-concepts/model-querying-finders/#findbypk[la méthode `findByPk`]  de sequelize :

[source ,typescript]
----
// notes.service.ts
async find(noteId: number): Promise<Note> {
    return await this.noteModel.findByPk(noteId);
}
----

On peut customiser le paramètre d'URL, si on souhaite paramétrer les URL avec le titre d'une note plutôt qu'un ID, dans ce cas, il faudra aussi changer la requête du service  et utiliser https://sequelize.org/docs/v6/core-concepts/model-querying-finders/#findone[la méthode `findOne`] de sequelize.

== Update

Pour la fonctionnalité de mise à jour, on souhaite persister les données en BDD, il nous faut une nouvelle méthode et un nouveau DTO qui héritera du précédent.

[background-color=var(--r-demonstration)]
=== Update : le DTO

Voici ce nouveau DTO :

[source ,typescript]
----
// dto/update-note.dto.ts
import { PartialType } from '@nestjs/mapped-types';
import { CreateNoteDto } from './create-note.dto';

export class UpdateNoteDto extends PartialType(CreateNoteDto) {}
----

=== Update : le DTO

Comme préciser dans https://docs.nestjs.com/techniques/validation#mapped-types[la documentation de Nest], on a une classe qui hérite du premier DTO, et qui précise que l'on pourrait recevoir que partiellement le type `CreateNoteDto`.

En effet, on ne veut pas forcément tout modifier sur la note, l'objet sera donc partiel.

[NOTE.speaker]
--
Au moment voulu, on pourra le modifier pour y inclure l'ID de ceux qui ont modifié une note, ajouter des collaborateurs etc, etc.
--

[background-color=var(--r-demonstration)]
=== update : le contrôleur

Voici la méthode update du contrôleur, cette méthode possède un nouveau décorateur : `@Patch`

`Patch` est la méthode HTTP utilisé pour mettre à jour une ressource.

N'oublions pas d'importer le nouveau DTO dans le contrôleur.

On a ajouté le suffix `/update` à l'URL pour être constant et on a enlevé le décorateur `@Redirect` :

[source,typescript]
----
// notes.controller.ts
import {/*...*/,  Patch } from '@nestjs/common';
import { UpdateNoteDto } from './dto/update-note.dto';
// ...
@Patch(':id/update')
update(@Param('id') id: string, @Body() updateNoteDto: UpdateNoteDto) {
    return this.notesService.update(+id, updateNoteDto);
}
----

[background-color=var(--r-demonstration)]
=== update : le service

Voyons la méthode update du service `notes` :

[source ,typescript]
----
import { UpdateNoteDto } from './dto/update-note.dto';
// notes.service.ts
async update(id: number, updateNoteDto: UpdateNoteDto) {
    return await this.noteModel.update(updateNoteDto, { where: { id } });
}
----

Rien de particulier, si ce n'est que l'on continue à utiliser le DTO et qu'il faut donc l'importer.

À ce stade, on devrait pouvoir effectuer une mise à jour avec Insomnia.

== destroy

L'effacement de données est la plus simple des fonctionnalités, tellement simple qu'il faut demander à l'utilisateur s'il est sûr de lui, on vous laissera implémenter ça côté front, on a choisi le décorateur `@Delete` pour cette fonctionnalité.

C'est la méthode http a utilisé pour ce genre de fonctionnalité.

Voici ce que ça donne dans le contrôleur :

[source ,typescript]
----
import { /* ... */, Delete } from '@nestjs/common';
// notes.controller.ts
@Delete(':id/delete')
async destroy(@Param('id') id: string) {
    return await this.notesService.destroy(+id);
}
----

[background-color=var(--r-demonstration)]
=== destroy

Et voici ce que ça donne dans le service :

[source ,typescript]
----
// notes.service.ts
async destroy(id: number) {
    return await this.noteModel.destroy({ where: { id } });
}
----

== Authentification avec JWT

On a fait en sorte de modifier nos fonctionnalités pour gérer uniquement le format JSON.

Pour réussir, on a dû annuler notre fonctionnalité d'authentification, car on n'utilise plus de session.

Dans ce module, on va voir comment implémenter un système d'authentification en utilisant les JSON Web Token (JWT)

* https://jwt.io[]
* https://docs.nestjs.com/security/authentication#jwt-token[]

[background-color=var(--r-oclock-color)]
== JWT : définition

Les JWT sont un standard  qui permet de transmettre des informations de façon sécurisée au sein d'une chaîne de caractères chiffrée.

L'aspect sécurité s'entend par le fait que la validité du token est vérifié par le biais d'une clé que l'on doit garder secrète et qui sert à confirmé (ou non) l'intégrité des données(non modifiées), et également d'une date limite de validité.

Les données contenues dans un token sont lisibles par tout le monde, n'importe qui peut déchiffrer un JWT,  on n'y stockera donc jamais d'informations sensibles (mot de passe, etc).

[background-color=var(--r-oclock-color)]
== JWT

On va se servir de ce token comme d'un lien entre le front et le back, on va le transférer du serveur au front, et du front au serveur où il sera systématiquement vérifié avant d'autoriser l'exécution des fonctionnalités.

[background-color=var(--r-oclock-color)]

=== JWT : Guard

On doit implémenter un nouveau _Guard_, c'est lui qui interceptera la requête et validera ou non le token.

On s'en servira à chaque fois que c'est approprié, c'est-à-dire sur les routes que l'on souhaite protéger.

[background-color=var(--r-demonstration)]
=== JWT : Guard

Voici ce guard, on a repris celui fourni dans la doc, on a juste modifié la ligne qui permet de vérifier le token pour lui donner le secret correct :

[source,typescript]
----
// guards/auth.guard.ts
import { CanActivate, ExecutionContext, Injectable, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { Request } from 'express';

@Injectable()
export class AuthGuard implements CanActivate {
    constructor(private jwtService: JwtService) {}

    async canActivate(context: ExecutionContext): Promise<boolean> {
        const request = context.switchToHttp().getRequest();
        const token = this.extractTokenFromHeader(request);
        if (!token) {
            throw new UnauthorizedException();
        }

        try {
            const payload = await this.jwtService.verifyAsync(token, {
                secret: process.env.JWT_SECRET,
            });
            // 💡 We're assigning the payload to the request object here
            // so that we can access it in our route handlers
            request['user'] = payload;
        } catch {
            throw new UnauthorizedException();
        }
        return true;
    }

    private extractTokenFromHeader(request: Request): string | undefined {
        const [type, token] = request.headers.authorization?.split(' ') ?? [];

        return type === 'Bearer' ? token : undefined;
    }
}
----

=== JWT : implémentation

Ensuite, on doit modifier le Guard `roles.guard` pour lui dire de décoder le token et d'aller chercher un utilisateur afin de vérifier ses rôles (le code suivant ne montre que les modifications apportées au Guard) :

[source,typescript]
----
// roles.guard.ts
import { /* ... */, UnauthorizedException } from '@nestjs/common';
// ...
import { JwtService } from '@nestjs/jwt';
import { UserService } from '../users/user.service';

@Injectable()
export class RolesGuard implements CanActivate {
    constructor(
        // ...
        private jwtService: JwtService,
        private userService: UserService
    ) {}

    async canActivate(context: ExecutionContext) {
        // ...
        const request = context.switchToHttp().getRequest();
        const token = request.headers.authorization.split(' ')[1];

        try {
            const decoded = await this.jwtService.verifyAsync(token, {
                secret: process.env.JWT_SECRET,
            });

            const user = await this.userService.findOne(decoded.userId);
            const userRoles = user.roles.map((role: Role) => role.name);
            request['userId'] = decoded.userId;
            return requiredRoles.some(
                (role: string) =>
                    userRoles?.includes(role) || userRoles?.includes('admin')
            );
        } catch {
            throw new UnauthorizedException();
        }
    }
}

=== JWT : le front

On teste le tout avec une requête `fetch`.

On exécute le code suivant depuis un navigateur.

[source,javascript]
----
async function login() {
    const data = {
        email: 'admin@admin.com',
        password: 'secret',
    };

    const res = await fetch('http://localhost:3000/auth/login', {
        headers: {
            'content-type': 'application/json',
        },
        method: 'POST',
        body: JSON.stringify(data),
    });

    return await res.json();
}

async function getNotes(token) {
    const res = await fetch('http://localhost:3000/notes', {
        headers: {
            'content-type': 'application/json',
            authorization: `Bearer ${token}`,
        },
        method: 'GET',
    });

    return await res.json();
}

// IIFE => https://developer.mozilla.org/en-US/docs/Glossary/IIFE
(async () => {
    const res = await login();
    const data = await getNotes(res.user.access_token);
    console.log(data);
})();
