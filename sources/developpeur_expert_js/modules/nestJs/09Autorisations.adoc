== Autorisations

On a l'authentification en place, mais on a toujours un problème, il faut restreindre la lecture, l'édition et l'effacement de données qui n'appartiennent pas à un utilisateur.

Autrement dit, il faut s'assurer que les utilisateurs soient autorisés à effectuer certaines actions.


== Autorisations : les étapes

Au vu du choix de conception que nous avons fait (RBAC), on va avoir plein de possibilités pour mettre en place ces autorisations, et on pourra être très fin dans la gestion des permissions.

Il y aura plusieurs étapes à réaliser, que voici :

* Création d'un guard (sorte de middleware)
* Un middleware isAdmin (un admin peut tout faire)
* Un type enums qui représentent les rôles disponibles en BDD

On suit, pas à pas, ce qui est décrit dans la doc : https://docs.nestjs.com/security/authorization[Doc]

== Autorisations : les étapes

On va commencer par faire le middleware d'admin, pour se simplifier la vie, on va déjà modifier la requête qui permet de récupérer un utilisateur.

On va aller chercher ses rôles et permissions en même temps.

On va montrer quelques exemples, on n'a pas le temps de tout montrer, il faudra surtout retenir les principes.

== Le middleware isAdmin

Un admin doit pouvoir accéder à toute l'application sans restriction, ce qui veut dire que même si un admin n'a pas créé une ressource, il doit pouvoir y accéder et la modifier ou l'effacer, à des fins de modération par exemple.

Le middleware lui-même n'est pas très compliqué dans ce qu'il doit faire (vérifier un rôle), c'est son application qui soulève une question.

== Le middleware isAdmin : application

Comment applique-t-on de middleware ?

On le mettra là où on veut restreindre l'accès aux admins, pour autoriser un admin à accéder à n'importe quel route, on modifiera le `guard` qui permet de vérifier les rôles.


== Démonstration 02

isAdmin middleware

// tag::demo[]
[NOTE.speaker]
--
*isAdmin middleware*

Voici le middleware en question :

[source ,typescript]
----
// src/common/middlewares/isAdmin.ts
import {
    Injectable,
    NestMiddleware,
    HttpException,
    HttpStatus,
} from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';
import { User } from '../../users/entities/user.entity';

@Injectable()
export class IsAdminMiddleware implements NestMiddleware {
    async use(req: Request, res: Response, next: NextFunction) {
        const { id } = req.session['user'];
        // Aller chercher l'utilisateur avec le rôle qui lui est attribué
        const user = await User.findByPk(id, {
            include: { all: true, nested: true },
        });

        let role = null;

        if (user.dataValues.hasOwnProperty('roles')) {
            role = user.dataValues.roles.find(
                role => role.name === process.env.ADMIN
            );
        }
        if (role) {
            return next();
        }

        throw new HttpException('Forbidden', HttpStatus.FORBIDDEN);
    }
}
----

*isAdmin middleware : restriction des routes aux admins uniquement*

C'est le plus simple à mettre en place, on copie ce qu'on a fait pour le middleware d'authentification, et on bloque les contrôleurs que l'on veut, avec la possibilité d'exclure certaines routes.

On ajoute la ligne suivante dans le module `App` :
[source ,typescript]
----
consumer.apply(IsAdminMiddleware).forRoutes('notes');
----

Lisons la doc pour voir comment customiser le comportement de ce middleware

https://docs.nestjs.com/middleware#excluding-routes[Doc middleware]

*isAdmin middleware : ouvertures des routes restreintes à certains rôles*

Pour ouvrir les routes à tous les admins, on doit modifier légèrement le `AuthGuard` qu'on a fait, qui permet de donner un accès selon un rôle.

On va faire en sorte de retourner `true` si le rôle est le bon, ou si le rôle est `admin`.

Voici la dernière ligne du `Guard`.

[source ,typescript]
----
return (
    requiredRoles.some(role => userRoles?.includes(role))
    // est-ce qu'il y a "admin" dans les rôles ?
    || userRoles?.includes('admin')
);
----

Et c'est tout, on peut maintenant tester sur différentes routes.

== Exercice : Mise en place des autorisations RBAC

*Durée : 10 minutes*

=== Objectif
Mettre en place un système d'autorisations RBAC (Role Based Access Control) permettant de restreindre l'accès aux fonctionnalités de modification et suppression aux seuls administrateurs.

=== Prérequis
* Une base de données avec des utilisateurs
* Un système d'authentification fonctionnel
* Une table `roles` avec au moins un rôle "admin"

=== Étapes

1. Créer l'enum des rôles :
+
```typescript
// src/common/enums/roles.enum.ts
export enum Role {
  USER = 'user',
  ADMIN = 'admin'
}
```

2. Créer le décorateur de rôles :
* Créer un fichier `roles.decorator.ts`
* Implémenter le décorateur SetMetadata

3. Créer le guard de rôles :
* Créer un fichier `roles.guard.ts`
* Implémenter la logique de vérification des rôles
* Vérifier si l'utilisateur est admin

4. Appliquer les restrictions :
* Protéger les routes de modification (PUT/PATCH)
* Protéger les routes de suppression (DELETE)
* Laisser l'accès en lecture pour tous les utilisateurs authentifiés

=== Vérification
* Se connecter en tant qu'utilisateur normal et vérifier que les modifications sont impossibles
* Se connecter en tant qu'admin et vérifier que toutes les actions sont possibles
* Vérifier que la lecture reste accessible à tous les utilisateurs authentifiés

== Correction

[NOTE.speaker]
--
1. Création du décorateur de rôles :
+
```typescript
// src/common/decorators/roles.decorator.ts
import { SetMetadata } from '@nestjs/common';
import { Role } from '../enums/roles.enum';

export const ROLES_KEY = 'roles';
export const Roles = (...roles: Role[]) => SetMetadata(ROLES_KEY, roles);
```

2. Création du guard de rôles :
+
```typescript
// src/common/guards/roles.guard.ts
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Role } from '../enums/roles.enum';
import { ROLES_KEY } from '../decorators/roles.decorator';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    
    if (!requiredRoles) {
      return true;
    }

    const { user } = context.switchToHttp().getRequest().session;
    return requiredRoles.some((role) => user.roles?.includes(role)) || 
           user.roles?.includes(Role.ADMIN);
  }
}
```

3. Application dans le contrôleur :
+
```typescript
// src/notes/notes.controller.ts
@UseGuards(RolesGuard)
@Controller('notes')
export class NotesController {
  // ... autres méthodes

  @Roles(Role.ADMIN)
  @Put(':id')
  update(@Param('id') id: string, @Body() updateNoteDto: UpdateNoteDto) {
    return this.notesService.update(+id, updateNoteDto);
  }

  @Roles(Role.ADMIN)
  @Delete(':id')
  remove(@Param('id') id: string) {
    return this.notesService.remove(+id);
  }
}
```
