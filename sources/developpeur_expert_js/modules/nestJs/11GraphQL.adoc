== Qu'est-ce que GraphQL ?

GraphQL est un serveur de données qui n'est pas lié spécifiquement à un type de base de données, mais il peut être connecté à plusieurs bases de données de plusieurs types (SQL, NoSQL) ou tout autre fournisseur de données (Fichiers JSON, CSV, API tierces…).

GraphQL est à la fois un langage de requête pour les API et un environnement d'exécution pour ces requêtes.

GraphQL.js fournit deux fonctionnalités importantes : la création d'un schéma de type et la diffusion de requêtes sur ce schéma de type.

Avec GraphQL, on expose un schéma typé pour obtenir nos données, au lieu des routes des API REST traditionnelles.


[background-color="var(--r-oclock-color)"]
=== GraphQL : Avantages

On peut réconcilier des données en provenance de diverses bases de données et requêter uniquement les champs dont on a besoin.

[background-color="var(--r-oclock-color)"]
=== GraphQL : Inconvénients

Le nombre de requêtes généré par un serveur GraphQL.

En effet, si on configure GraphQL pour réconcilier des données depuis plusieurs Bases de Données, GraphQL devra multiplier les requêtes pour nous donner le résultat attendu.


[background-color="var(--r-oclock-color)"]
== Les concepts clés

* _**Schéma**_ : L'essentiel d'une implémentation GraphQL, ils décrivent les données dont pourra disposer le client.
* _**Query**_ : Requête pour récupérer ou lire des données.
* _**Mutation**_ : Une requête qui modifie des données.
* _**Type**_ : Définit la structure des données utilisées.
* _**Resolver**_ : Listes de fonctions qui procurent des réponses à une requête GraphQL. C'est comme un contrôleur, mais dédié à GraphQL.

=== Mise en place des modules

On ajoute les lignes suivantes dans `app.module.ts` :

[source,typescript]
----
// app.module.ts
import { GraphQLModule } from '@nestjs/graphql';
@Module({
  imports: [
    //...
    GraphQLModule.forRoot({ autoSchemaFile: 'schema.gql' }),
  ],
})
----

On précise l'option `{ autoSchemaFile: 'schema.gql' }`, pour générer un schéma automatiquement, on utilise la méthode `code first` pour tirer parti des avantages de typescript (annotations et décorateurs).

[NOTE.speaker]
--
* https://docs.nestjs.com/graphql/quick-start#overview[différence entre `code first` et `schema first`]
* https://docs.nestjs.com/graphql/quick-start#code-first[méthode code first]
--

On trouvera le fichier *schema.gql* dans notre répertoire de travail, ce fichier est géré par GraphQL et sera mis à jour à chaque fois qu'on crée une requête ou un type GraphQL.

== Types et resolvers

[background-color="var(--r-oclock-color)"]
=== Types

On va déjà créer un type (ObjectType), afin de faire taire l'erreur GraphQL, ensuite, on verra pour un resolver qui permettra de lire les données. Le type doit matcher avec le schéma que l'on a d'une table en BDD.

On fait ce qu'on appelle un `ObjectType`, qui représente un objet que l'on peut requêter, en gros, c'est un modèle  :

https://graphql.org/learn/schema/#object-types-and-fields[Voici la doc]

[background-color="var(--r-demonstration)"]
=== ObjectType

On fait un fichier `src/movie/movie.type.ts` :

[source,typescript]
----
// src/movie/movie.type.ts
import { ObjectType, Field, ID } from '@nestjs/graphql';
// On nomme le MovieType Movie en passant une arg dans le décorateur.
@ObjectType('Movie')
// Le schéma doit correspondre à ce qu'on a en BDD
export class MovieType {
  // Pour les ID, on peut être explicite, car GraphQL possède un type ID
  // Le décorateur field est là pour indiquer à GraphQL que nous avons des champs sur lesquels on veut faire des requêtes
  @Field((type) => ID)
  id: number;
  @Field()
  image: string;
  @Field()
  title: string;
  @Field()
  description: string;
  // L'année seulement, donc un nombre
  @Field()
  release_year: number;
  @Field({ nullable: true })
  directors: string;
  @Field({ nullable: true })
  countries: string;
  @Field()
  imdb_id: string;
  @Field()
  created_at: Date;
  @Field({ nullable: true })
  updated_at: Date;
}
----

On a indiqué que certains champs pourraient être `null`, si on ne le fait pas et que la Base de données ne renvoie rien, on aurait une erreur.

[background-color="var(--r-demonstration)"]
=== Resolvers

Les resolvers agissent comme des contrôleurs, mais seulement pour GraphQL, on ne fera pas de rendu de vues avec ça.

On va créer un resolver, qui va nous permettre de faire une requête, il retournera pour l'instant des fausses données, on branchera ensuite la BDD et on verra comment obtenir les vraies données.

[source,typescript]
----
import { Resolver, Query } from '@nestjs/graphql';
import { MovieType } from './movie.type';
// Que résoud on ? que recherche-t-on comme données ?
@Resolver((of) => MovieType)
export class MovieResolver {
  // Que retourne la requête movies() ?
  @Query((returns) => MovieType)
  movies() {
    return {
      id: 123,
      title: "'Titre du film'",
      image: 'https://picsum.photos/200/300',
      imdb_id: 'ID IMDB',
      created_at: new Date().toISOString(),
    };
  }
}
----

[background-color="var(--r-oclock-color)"]
=== Les décorateurs `@Query` et `@Resolver`

La classe `MovieResolver` est décorée avec cette ligne : `@Resolver((of) => MovieType)` qui indique à graphQL que cette classe gère la ressource `MovieType`.

La méthode `movies()` est décoré avec `@Query` qui prend en argument le type de données que retournera la méthode.

On doit ajouter ce `Resolver` dans le tableau des providers au module `Movie` :

[source, typescript]
----
// src/movie/movie.module.ts
// ...
import { MovieResolver } from './movie.resolver';

@Module({
  providers: [MovieResolver],
})
----

== Une Query dynamique

Maintenant que tout est branché, on peut faire notre première requête dynamique en utilisant GraphQL. Pour ça, on va modifier la _vraie/fausse_ requête que l'on a fait précédemment pour lui dire d'utiliser le service que l'on vient de faire.

On va injecter le service dans le resolver, et s'en servir pour exécuter une requête.

[background-color="var(--r-demonstration)"]
=== Une Query dynamique

[source,typescript]
----
// movie.resolver.ts
// ...
import { MovieService } from './movie.service';
export class MovieResolver {
  constructor(private movieService: MovieService) {}
  // Que retourne la query ?
  @Query((returns) => [MovieType])
  async movies(): Promise<MovieType[]> {
    return this.movieService.findAll();
  }
----

Le décorateur `@Query` retourne à présent un tableau d'objets `MovieType` et la méthode demande les données à Prisma par le biais du service.

[background-color="var(--r-oclock-color)"]
=== Une Query dynamique

On teste tout ça dans la sandbox, et si tout se passe bien, on obtient un tableau de nos objets.

== Les Mutations

En langage GraphQL, une mutation est une opération qui modifie, efface ou crée des données.

Nous allons voir comment créer des données, les autres fonctionnalités vous serviront d'exercices.

On doit introduire deux nouveaux décorateurs, `@Args` et `@Mutation`, tous deux provenant du module `@nestjs/graphql`.

Le premier permettra de récupérer les infos d'un formulaire, le second, dit quoi faire à GraphQL.

[background-color="var(--r-oclock-color)"]
=== Une Mutation : créer une ressource

Les mutations sont un peu plus complexes à réaliser et un peu fastidieuses, car il faut lister tous les champs qui nous intéressent à la main si on utilise `@Args`. On peut toutefois simplifier l'opération si on crée un `InputType`.

Ce type permettra à GraphQL d'accepter un objet dans le décorateur `@Arg` plutôt que de faire la liste des champs à chaque fois, on le fait dans le type une fois et on pourra s'en resservir.


[background-color="var(--r-demonstration)"]
=== Une Mutation : créer une ressource

Dans le répertoire, on fait un fichier `movie.input.ts`, dont voici le contenu :

[source,typescript]
----
import { InputType, Field } from '@nestjs/graphql';
@InputType()
export class MovieInput {
  @Field()
  image: string;
  @Field()
  title: string;
  @Field()
  description: string;
  @Field()
  release_year: number;
  @Field({ nullable: true })
  directors?: string;
  @Field({ nullable: true })
  countries?: string;
  @Field()
  imdb_id: string;
  @Field()
  created_at: Date;
  @Field({ nullable: true })
  updated_at?: Date;
}
----

[background-color="var(--r-oclock-color)"]
=== Une Mutation : créer une ressource

Ce code ressemble fortement au `MovieType` que l'on a fait précédemment, mais son rôle est de vérifier les données d'un formulaire envoyé par un client.


[background-color="var(--r-demonstration)"]
=== Une Mutation : créer une ressource

On crée une méthode décorée avec `@Mutation` dans le `MovieResolver`, cette méthode appellera le service movie afin de créer une ressource.

[source,typescript]
----
@Mutation((returns) => MovieType)
  // * On passe une string au décorateur @Args pour nommer l'objet qu'on va recevoir
  async create(@Args('data') data: MovieInput) {
    const movie = await this.movieService.create(data);
    return movie;
  }
----

Pour créer le movie, rien de plus simple, voici la méthode à ajouter dans le service :

[source,typescript]
----
async create(data: MovieInput): Promise<MovieType> {
    return await this.prismaService.movie.create({ data });
  }
----

[background-color="var(--r-oclock-color)"]
=== Une Mutation : créer une ressource

On teste dans la sandbox et on devrait obtenir en retour un objet fraichement créé.
