== Introduction à RESTDataSource

Apollo Server permet de récupérer des données d’API REST en utilisant la classe `RESTDataSource`. Cette classe fournit des fonctionnalités comme la gestion des requêtes HTTP, la mise en cache, et la déduplication des requêtes, simplifiant l'intégration de sources de données externes dans le serveur Apollo.

[NOTE.speaker]
====
L'implémentation de `RESTDataSource` permet de récupérer des données depuis des API externes directement dans Apollo Server, ce qui améliore les performances en réduisant les requêtes redondantes.
====

== Étape 1 : Installation de RESTDataSource

Installez le package `@apollo/datasource-rest` pour utiliser `RESTDataSource`. Si vous avez précédemment utilisé Axios pour les appels API, vous pouvez également le désinstaller, car il ne sera plus nécessaire.

[source,bash]
----
npm install @apollo/datasource-rest
npm uninstall axios
----

[NOTE.speaker]
====
Nous n'avons plus besoin d’Axios, car `RESTDataSource` fournit déjà des méthodes pour effectuer des requêtes HTTP. `RESTDataSource` nous permet d’ajouter facilement de la logique de mise en cache, de déduplication et de transformation des données au niveau du serveur.
====

== Étape 2 : Mise à jour de la classe WeatherAPI

Pour structurer notre code, renommez le dossier `services` en `datasources`, puis modifiez la classe `WeatherAPI` pour qu'elle hérite de `RESTDataSource`. Cette classe servira de source de données pour récupérer des informations météorologiques.

1. Dans `src/datasources/WeatherAPI.ts`, modifiez la classe pour qu’elle hérite de `RESTDataSource`.
2. Configurez l’URL de base de l’API météo dans le constructeur de la classe.

[source,typescript]
----
// src/datasources/WeatherAPI.ts
import { RESTDataSource } from '@apollo/datasource-rest';

class WeatherAPI extends RESTDataSource {
  constructor() {
    super();
    this.baseURL = 'https://api.tomorrow.io/v4/';
  }
}
----

[NOTE.speaker]
====
L’URL de base est spécifiée dans le constructeur pour simplifier les appels API en définissant un point de départ commun pour chaque requête.
====

== Étape 3 : Implémentation de la méthode findByCoordinates

La méthode `findByCoordinates` récupère les données météorologiques en fonction de coordonnées géographiques (latitude et longitude).

1. Modifiez `findByCoordinates` pour utiliser la méthode `get` de `RESTDataSource`.
2. Utilisez la méthode `willSendRequest` pour ajouter automatiquement la clé API (stockée dans les variables d'environnement) et définir l'unité de température en Celsius.

[source,typescript]
----
// src/datasources/WeatherAPI.ts

class WeatherAPI extends RESTDataSource {
  constructor() {
    super();
    this.baseURL = 'https://api.tomorrow.io/v4/';
  }

  willSendRequest(request) {
    request.params.set('appid', process.env.TOMORROW_API_KEY);
    request.params.set('units', 'metric');
  }

  async findByCoordinates(latitude, longitude) {
    return this.get('weather', {
      lat: latitude,
      lon: longitude,
    });
  }
}
----

[NOTE.speaker]
====
Avec `willSendRequest`, nous injectons automatiquement la clé API dans chaque requête, ainsi que l'unité de température pour s'assurer que toutes les réponses sont en Celsius.
====

== Étape 4 : Fournir la source de données au contexte Apollo

Pour que le serveur Apollo utilise `WeatherAPI` comme source de données, ajoutez une instance de `WeatherAPI` dans la fonction de contexte, et liez-la à la propriété `cache` du serveur pour bénéficier de la mise en cache des réponses.

1. Modifiez le fichier `src/index.ts` pour créer une instance de `WeatherAPI` dans le contexte.

[source,typescript]
----
// src/index.ts
import { ApolloServer } from 'apollo-server';
import WeatherAPI from './datasources/WeatherAPI';

const server = new ApolloServer({
  typeDefs,
  resolvers,
  context: () => ({
    dataSources: {
      weatherAPI: new WeatherAPI(),
    },
  }),
});

server.listen().then(({ url }) => {
  console.log(`🚀 Server ready at ${url}`);
});
----

[NOTE.speaker]
====
En ajoutant `weatherAPI` au contexte, les résolveurs peuvent maintenant accéder à cette source de données pour récupérer les données météorologiques en utilisant `RESTDataSource`.
====

== Étape 5 : Mise en cache et déduplication des requêtes

L’instance de `RESTDataSource` fournit une mise en cache et une déduplication automatiques pour les requêtes `GET` identiques. Si plusieurs requêtes identiques sont effectuées simultanément, `RESTDataSource` enverra une seule requête et utilisera le même résultat pour toutes.

[NOTE.speaker]
====
La mise en cache réduit la charge sur l’API externe en évitant les appels redondants. Les réponses sont mises en cache dans une mémoire interne, mais des solutions plus avancées comme Redis ou Memcached peuvent être intégrées pour une mise en cache persistante.
====

== Étape 6 : Utilisation de la source de données dans les résolveurs

Pour finaliser l'implémentation, mettez à jour le résolveur du champ `weather` afin qu'il utilise `WeatherAPI` depuis le contexte pour récupérer les données météorologiques.

1. Modifiez le fichier `src/schema/Weather.ts` et configurez le résolveur pour utiliser la méthode `findByCoordinates` de `WeatherAPI`.

[source,typescript]
----
// src/schema/Weather.ts

const resolvers = {
  Query: {
    weather: async (_, { latitude, longitude }, { dataSources }) => {
      return dataSources.weatherAPI.findByCoordinates(latitude, longitude);
    },
  },
};

export default resolvers;
----

[NOTE.speaker]
====
Cette intégration permet de récupérer directement les données depuis l'API météo, avec les avantages de mise en cache et de déduplication fournis par `RESTDataSource`.
====
