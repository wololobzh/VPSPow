== Introduction aux mutations dans GraphQL

Les mutations dans GraphQL permettent de **créer**, **mettre à jour** et **supprimer** des données. Elles agissent comme des opérations de modification de l'état du serveur, similaires aux opérations CRUD (Create, Read, Update, Delete) d'une API REST.

[NOTE.speaker]
====
Les mutations sont essentielles pour modifier des données en GraphQL, contrairement aux requêtes (queries) qui sont généralement utilisées pour récupérer des données. Par convention, elles sont définies dans le type `Mutation` des schémas GraphQL.
====

== Étape 1 : Création des schémas de mutations

1. Créez un fichier `Mutation.gql` dans le dossier des schémas pour définir les mutations.

[source,bash]
----
touch src/schemas/Mutation.gql
----

Dans ce fichier, ajoutez les mutations `createRestaurant` et `createCity`. Ces mutations prendront en paramètre des types d'entrées spécifiques, que nous allons définir dans les fichiers de schéma pour chaque entité.

**Exemple de schéma :**

[source,graphql]
----
type Mutation {
  createRestaurant(data: NewRestaurant!): Restaurant
  createCity(data: NewCity!): City
}
----

[NOTE.speaker]
====
Dans ce schéma, chaque mutation renvoie un objet du type de l’entité qu'elle crée. Par exemple, `createRestaurant` renverra un objet de type `Restaurant`.
====

== Étape 2 : Ajout des types d'entrée des mutations

Dans les fichiers `Restaurant.gql` et `City.gql` du dossier `src/schemas`, ajoutez les types `NewRestaurant` et `NewCity` pour définir les données nécessaires à la création des entités `Restaurant` et `City`.

**Exemple de type d'entrée :**

[source,graphql]
----
input NewRestaurant {
  name: String!
  cityId: ID!
  managerId: ID!
  cuisinesIds: [ID]
}

input NewCity {
  name: String!
  postcode: String!
  latitude: Float!
  longitude: Float!
}
----

[NOTE.speaker]
====
Les champs de ces types d'entrée sont les données requises pour créer chaque entité. Par exemple, `NewRestaurant` inclut le `name`, le `cityId` (identifiant de la ville associée), et les `cuisinesIds` pour les types de cuisine que le restaurant propose.
====

== Étape 3 : Lecture des fichiers par Apollo Server

Pour que le serveur Apollo prenne en compte les mutations, ajoutez le fichier `Mutation.gql` dans le fichier `src/schemas/index.ts` qui centralise les schémas.

[source,typescript]
----
import { gql } from 'apollo-server';

import RestaurantSchema from './Restaurant.gql';
import CitySchema from './City.gql';
import MutationSchema from './Mutation.gql';

export default gql`
  ${RestaurantSchema}
  ${CitySchema}
  ${MutationSchema}
`;
----

[NOTE.speaker]
====
L'ajout de `Mutation.gql` dans l'index permet à Apollo Server de lire les définitions de mutations et de les rendre disponibles pour exécution.
====

== Étape 4 : Création des résolveurs de mutations

Pour chaque mutation, créez un résolveur qui gère la logique métier correspondante.

1. Dans le dossier `src/resolvers`, créez un sous-dossier `mutations` pour organiser les résolveurs de mutations.
2. Dans ce sous-dossier, créez les fichiers `Restaurant.ts` et `City.ts` pour contenir les résolveurs `createRestaurant` et `createCity`.

**Exemple de résolveur :**

[source,typescript]
----
// src/resolvers/mutations/Restaurant.ts
export const createRestaurant = async (parent, { data }, context) => {
  // Exemple de logique : création d’un restaurant
  const newRestaurant = await context.db.Restaurant.create({
    data: {
      name: data.name,
      cityId: data.cityId,
      managerId: data.managerId,
      cuisines: {
        connect: data.cuisinesIds.map(id => ({ id })),
      },
    },
  });
  return newRestaurant;
};
----

Répétez cette démarche pour `createCity` dans `City.ts`.

[NOTE.speaker]
====
La logique de chaque mutation est gérée dans son résolveur respectif, par exemple, `createRestaurant` prend les `data` fournies et les utilise pour insérer un nouvel enregistrement dans la base de données.
====

== Étape 5 : Organisation des résolveurs de mutations

Pour centraliser et organiser les résolveurs de mutations, ajoutez un fichier `index.ts` dans `src/resolvers/mutations` :

[source,typescript]
----
// src/resolvers/mutations/index.ts
import { createRestaurant } from './Restaurant';
import { createCity } from './City';

export default {
  Mutation: {
    createRestaurant,
    createCity,
  },
};
----

Ensuite, importez les mutations dans le fichier principal des résolveurs `src/resolvers/index.ts`.

[source,typescript]
----
import mutations from './mutations';

export default {
  Query: { /* vos requêtes */ },
  Mutation: mutations.Mutation,
};
----

[NOTE.speaker]
====
Cette organisation des résolveurs permet de structurer le code en modules, facilitant ainsi sa maintenance et son évolution.
====

== Exécution des mutations dans GraphQL Playground

Une fois les mutations configurées, nous pouvons les exécuter via GraphQL Playground. Exemple pour créer une ville :

**Requête de mutation :**

[source,graphql]
----
mutation CreateCity($data: NewCity!) {
  createCity(data: $data) {
    id
    name
    postcode
  }
}
----

**Variables :**

[source,json]
----
{
  "data": {
    "name": "O'Clock City",
    "postcode": "123456",
    "latitude": 135,
    "longitude": 246
  }
}
----

[NOTE.speaker]
====
Dans cet exemple, nous créons une nouvelle ville avec un code postal unique. Si nous tentons de créer une ville avec le même code postal, une erreur sera renvoyée.
====
