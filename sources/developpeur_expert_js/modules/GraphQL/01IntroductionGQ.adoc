== GraphQL, c'est quoi ?

GraphQL est un langage de requêtes pour les API, qui permet aux clients de demander précisément les données dont ils ont besoin.

//image::./assets/GraphQL_logo.png[Logo de GraphQL,480]

[NOTE.speaker]
====
GraphQL, développé par Facebook en 2012, vise à optimiser la gestion des données dans les applications modernes en permettant de récupérer plusieurs ressources en une seule requête. Contrairement à REST, où chaque point de terminaison est conçu pour une ressource spécifique, GraphQL centralise les données en un point d'accès unique.
====

== Définition de GraphQL

GraphQL simplifie l'interaction entre les clients et serveurs en permettant de :

- Définir précisément les données à récupérer.
- Réduire le nombre de requêtes nécessaires.
- Faciliter l'ajout de nouvelles fonctionnalités sans altérer l'existant.

[NOTE.speaker]
====
GraphQL permet d’améliorer l'efficacité de l'application et de minimiser les échanges avec le serveur en offrant un accès structuré et flexible aux données.
====

== Fonctionnement de GraphQL

Le client envoie une requête en spécifiant les champs souhaités, et le serveur retourne une réponse structurée en fonction de cette requête.

[NOTE.speaker]
====
Dans GraphQL, chaque requête est entièrement définie par le client, ce qui permet de mieux contrôler les données transférées et d'éviter les informations inutiles. C'est un gain de performance important pour les applications mobiles et web, où les ressources réseau doivent être optimisées.
====

== Les différences entre GraphQL et REST

=== GraphQL

- Un seul point d'accès pour toutes les données.
- Les données sont renvoyées en fonction de la requête, permettant d'éviter le sur- et sous-chargement.
  
=== REST

- Plusieurs endpoints correspondant à différentes ressources.
- Peut nécessiter plusieurs appels pour obtenir des données liées.

[NOTE.speaker]
====
Contrairement à REST, qui repose sur de multiples endpoints, GraphQL offre une flexibilité accrue en unifiant les accès. Cela signifie que les développeurs n'ont pas besoin de définir de multiples points d'accès ou de points de terminaison, ce qui simplifie le code et réduit la maintenance.
====

== Avantages et inconvénients de GraphQL

*Avantages*
- Flexibilité des requêtes
- Optimisation des données reçues
- Forte scalabilité pour les applications modernes

*Inconvénients*
- Complexité de mise en œuvre initiale
- Possibilité de surcharge du serveur avec des requêtes trop larges
- Nécessite un monitoring des requêtes pour éviter des abus

[NOTE.speaker]
====
GraphQL peut devenir une solution très puissante, mais il est crucial de mettre en place des protections pour éviter des requêtes excessivement lourdes. Cela inclut des limitations côté serveur et des pratiques de requêtes côté client.
====

== Exemples de requêtes basiques

[source,graphql]
----
{
  user(id: "1") {
    name
    email
    posts {
      title
      content
    }
  }
}
----

Cette requête récupère le nom, l'email et les publications d'un utilisateur en une seule requête.

[NOTE.speaker]
====
Dans cet exemple, on voit comment une seule requête permet d'obtenir plusieurs informations en une fois, y compris des informations relationnelles (par exemple, les publications d'un utilisateur). GraphQL rend la récupération des données relationnelles plus simple et plus performante.
====

== Schéma de base de GraphQL

Chaque API GraphQL est définie par un schéma qui décrit les types d'objets et les relations entre eux.

=== Exemples de types dans un schéma GraphQL

[source,graphql]
----
type User {
  id: ID!
  name: String!
  email: String!
}

type Post {
  id: ID!
  title: String!
  content: String
  author: User
}
----

[NOTE.speaker]
====
Ici, on définit deux types principaux : `User` et `Post`, chacun ayant ses propres propriétés. `User` et `Post` peuvent être liés grâce aux types de données, ce qui permet de définir des relations entre les objets du schéma.
====

== Pourquoi utiliser GraphQL ?

GraphQL permet une meilleure gestion des données pour des applications modernes avec un backend riche, surtout dans des environnements où l’optimisation des ressources réseau est cruciale.

[NOTE.speaker]
====
GraphQL est particulièrement utile dans les applications nécessitant une grande flexibilité de requêtes et une scalabilité accrue. Sa capacité à limiter les données transférées au strict nécessaire est un atout pour les projets mobiles et web.
====

== Cas d'utilisation communs de GraphQL

* Applications mobiles nécessitant des données minimales.
* Frontends complexes avec de multiples interactions de données.
* Applications nécessitant des données dynamiques sans surcharge de requêtes.

[NOTE.speaker]
====
Ces cas d'utilisation montrent la pertinence de GraphQL dans des applications modernes, où il est nécessaire de réduire les appels réseau et de centraliser les informations en une seule requête.
====
