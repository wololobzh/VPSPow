== Introduction aux Resolvers et au Contexte dans Apollo Server

Les resolvers sont au cœur des applications GraphQL, car ils définissent comment chaque champ dans le schéma GraphQL est peuplé avec des données. Dans ce module, nous allons créer des resolvers pour récupérer les données et configurer un contexte avec Prisma pour accéder facilement à la base de données.

[NOTE.speaker]
====
Les resolvers agissent comme des intermédiaires entre les requêtes GraphQL et les données sous-jacentes. Avec Prisma, nous simplifions les requêtes de base de données, ce qui permet une meilleure gestion des relations entre données.
====

== Étape 1 : Mise en place des Resolvers pour les Queries

Nous allons d'abord configurer un resolver pour le type `Query`. Ce resolver va intercepter les requêtes pour des données telles que `restaurants` ou `cities`.

[source,typescript]
----
src/resolvers/Query.ts

import { Context } from '../context';

export const Query = {
  restaurants: async (_parent, _args, context: Context) => {
    return context.prisma.restaurant.findMany();
  },
};
----

Ici, nous créons une fonction `restaurants` qui utilise Prisma pour récupérer la liste de tous les restaurants. Nous passons le `context` pour accéder à l'instance de Prisma.

[NOTE.speaker]
====
Le contexte est crucial pour partager des instances (comme Prisma) entre les resolvers, évitant la recréation d'instances inutiles. Cela rend l'accès aux données plus efficace et centralisé.
====

== Étape 2 : Mise en place du Contexte avec Prisma

Pour éviter d'importer directement Prisma dans chaque fichier de resolvers, nous allons définir un contexte global.

[source,typescript]
----
src/context.ts

import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

export interface Context {
  prisma: PrismaClient;
}

export const context: Context = { prisma };
----

Ensuite, nous ajoutons ce contexte dans la configuration d'Apollo Server.

[source,typescript]
----
src/index.ts

import { ApolloServer } from '@apollo/server';
import { context } from './context';
import { typeDefs } from './schema';
import { resolvers } from './resolvers';

const server = new ApolloServer({
  typeDefs,
  resolvers,
  context: async () => context,
});

server.listen().then(({ url }) => {
  console.log(`🚀 Server ready at ${url}`);
});
----

[NOTE.speaker]
====
En configurant le contexte, nous facilitons le partage des informations essentielles entre tous les resolvers. Apollo Server gère la création de ce contexte à chaque requête, garantissant ainsi un accès facile et sûr aux données de la base.
====

== Étape 3 : Configuration des Resolvers pour les Relations

Pour gérer les relations, nous allons créer des resolvers supplémentaires pour les entités liées, comme `Restaurant` et `City`.

[source,typescript]
----
src/resolvers/Restaurant.ts

import { Context } from '../context';

export const Restaurant = {
  city: async (parent, _args, context: Context) => {
    return context.prisma.city.findUnique({
      where: { id: parent.cityId },
    });
  },
  cuisines: async (parent, _args, context: Context) => {
    return context.prisma.cuisine.findMany({
      where: { restaurants: { some: { id: parent.id } } },
    });
  },
};
----

Nous avons ici des resolvers pour le champ `city` et `cuisines` d'un restaurant, ce qui nous permet de récupérer la ville et les cuisines associées à un restaurant spécifique.

[NOTE.speaker]
====
Les resolvers pour les relations permettent de récupérer les données associées sans charger systématiquement toutes les relations. Cela améliore les performances en évitant les chargements de données inutiles.
====

== Étape 4 : Utilisation du Contexte dans les Resolvers

Maintenant que le contexte est configuré, nous allons l’utiliser pour d'autres resolvers.

[source,typescript]
----
src/resolvers/City.ts

import { Context } from '../context';

export const City = {
  restaurants: async (parent, _args, context: Context) => {
    return context.prisma.restaurant.findMany({
      where: { cityId: parent.id },
    });
  },
};
----

Dans cet exemple, nous ajoutons un resolver pour récupérer les restaurants d’une ville spécifique, en utilisant le contexte pour accéder à Prisma.

[NOTE.speaker]
====
En accédant à Prisma via le contexte, nous maintenons une structure cohérente et évitons des importations multiples de l'instance Prisma, simplifiant ainsi le code.
====

== Étape 5 : Requêtes et Résolution avec Arguments

Pour améliorer la flexibilité de nos requêtes, nous ajoutons des filtres et paramètres.

[source,typescript]
----
src/resolvers/Query.ts

export const Query = {
  restaurant: async (_parent, { id }, context: Context) => {
    return context.prisma.restaurant.findUnique({ where: { id } });
  },
  cities: async (_parent, { filter }, context: Context) => {
    return context.prisma.city.findMany({
      where: filter,
    });
  },
};
----

Nous pouvons maintenant utiliser des arguments pour filtrer les résultats, par exemple, en récupérant un restaurant par son `id`.

[NOTE.speaker]
====
Les arguments dans GraphQL ajoutent de la flexibilité aux requêtes en permettant de spécifier les données à récupérer. Cela réduit la surcharge et améliore l'expérience utilisateur.
====

== Exemples de Requêtes

Une requête GraphQL pour récupérer un restaurant spécifique avec sa ville et ses cuisines associées :

```graphql
query GetRestaurant {
  restaurant(id: 1) {
    id
    name
    city {
      name
    }
    cuisines {
      name
    }
  }
}
```

Cette requête renvoie le restaurant avec son id, son name, ainsi que les informations de sa ville et de ses cuisines.

[NOTE.speaker]
====
Les requêtes GraphQL permettent de récupérer des données en fonction des relations entre entités, offrant ainsi une vision globale des données sans multiplications de requêtes complexes.
====
