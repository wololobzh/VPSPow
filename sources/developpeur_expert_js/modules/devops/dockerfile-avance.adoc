== Concepts avancés de Dockerfile

* **ARG** : Utilisé pour les variables en phase de build.
* **ENV** : Utilisé pour les variables en phase d'exécution.
* **Multi-stage build** : Technique pour réduire la taille des images.

[NOTE.speaker]
====
Les variables `ARG` sont disponibles uniquement pendant la construction de l'image, tandis que les variables `ENV` sont accessibles pendant l'exécution du conteneur. Le multi-stage build permet de créer des images Docker plus légères en utilisant plusieurs étapes de construction.
====

== ARG vs ENV

* **ARG** : Défini à l'aide de l'instruction `ARG`.
* **ENV** : Défini à l'aide de l'instruction `ENV`.

```dockerfile
ARG VERSION=20-alpine

FROM node:$VERSION

ENV NODE_ENV=production

RUN echo "Building version ${VERSION}, mode ${NODE_ENV}"

CMD ["/bin/sh", "-c", "echo Building version ${VERSION}, mode ${NODE_ENV}"]
```

* `docker build -t test --build-arg VERSION=14-alpine .` : Construit l'image avec la version 14.
* `docker run --env-file .env test` : Lance le conteneur avec les variables d'environnement dans un fichier `.env`.
* `docker run -e NODE_ENV=development test` : Lance le conteneur avec une variable d'environnement spécifique.

[NOTE.speaker]
====
Les variables `ARG` sont utiles pour passer des paramètres lors de la construction, tandis que `ENV` est utilisé pour configurer l'environnement d'exécution du conteneur.

Ici, la variable `VERSION` est définie avec `ARG` et utilisée pour spécifier la version de l'image de base. La variable `NODE_ENV` est définie avec `ENV` pour configurer l'environnement de production. Ils ne sont pas transmis au conteneur en cours d’exécution.
====

== Multi-stage build

* **Avantages** : Réduit la taille de l'image finale.
* **Utilisation** : Sépare les étapes de build et d'exécution.

[NOTE.speaker]
====
Le multi-stage build permet de copier uniquement ce qui est nécessaire pour l'exécution finale, en éliminant les fichiers temporaires et en réduisant la taille de l'image.
====

=== Exemple pratique : Backend Node.js

* Remplacer Directus par une application Node.js.
* Utiliser ARG, ENV, et multi-stage build pour construire l'image.

```dockerfile
# Étape 1 : Phase de build
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .

# Étape 2 : Phase de production
FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app .
ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "server.js"]
```

[NOTE.speaker]
====
Ce Dockerfile utilise deux étapes. La première étape installe les dépendances et construit l'application. La deuxième étape copie uniquement les fichiers nécessaires pour l'exécution, configurant l'environnement de production.
====

// tag::demo[]
=== Démonstration

Construire et analyser l'image Docker

[NOTE.speaker]
====
. Créer un fichier `Dockerfile` à la racine du projet.
. Insérer le contenu de l'exemple de Dockerfile.
. Ouvrir un terminal et naviguer vers le répertoire du projet.
. Exécuter `docker build -t my-node-app .` pour construire l'image.
. Analyser la taille de l'image avec `docker images`.
. Exécuter `docker run -p 3000:3000 my-node-app`.
. Accéder à l'application via `http://localhost:3000`.
====
