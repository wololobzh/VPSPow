== Introduction à PocketBase

* Base de données open source avec interface d'administration intégrée
* Backend tout-en-un : 
** Base de données
** API REST automatique 
** Authentification
** Stockage de fichiers
* Écrit en Go, distribué en binaire unique
* Idéal pour le prototypage et les petits projets

[NOTE.speaker]
====
PocketBase est une solution complète qui permet de créer rapidement un backend sans avoir à coder.
Il génère automatiquement une API REST à partir des collections créées dans l'interface d'administration.
Le fait d'avoir un binaire unique facilite grandement le déploiement.
====

=== Avantages de PocketBase

* Installation et configuration simples
* Interface d'administration intuitive
* API REST générée automatiquement
* Authentification intégrée
* Documentation complète
* Performances élevées

[NOTE.speaker]
====
PocketBase se distingue par sa simplicité d'utilisation tout en offrant des fonctionnalités avancées.
L'interface d'administration permet de gérer facilement les données et les utilisateurs.
La documentation est très bien faite et inclut des exemples pour différents langages.
====

== Installation et Configuration

=== Installation locale

* Téléchargement du binaire depuis GitHub
* Exécution directe sans dépendances
* Configuration minimale requise

[NOTE.speaker]
====
Le binaire est disponible pour Windows, Linux et MacOS.
Il suffit de le télécharger et de l'exécuter, pas besoin d'installer d'autres dépendances.
====

// tag::demo[]
=== Démonstration

**Installation et premier démarrage de PocketBase**

[NOTE.speaker]
====
* Télécharger le binaire :
```bash
curl -LO https://github.com/pocketbase/pocketbase/releases/download/v0.21.1/pocketbase_0.21.1_linux_amd64.zip
```

* Décompresser l'archive :
```bash
unzip pocketbase_*.zip
```

* Lancer PocketBase :
```bash
./pocketbase serve
```

* Montrer l'accès à l'interface d'administration sur http://127.0.0.1:8090/_/
* Créer le premier compte administrateur
====
// end::demo[]

== API REST Automatique

=== Points d'entrée générés

* CRUD complet :
** Create : POST /api/collections/posts/records
** Read : GET /api/collections/posts/records
** Update : PATCH /api/collections/posts/records/{id}
** Delete : DELETE /api/collections/posts/records/{id}

[NOTE.speaker]
====
L'API REST est générée automatiquement pour chaque collection.
Les points d'entrée suivent une convention simple et cohérente.
Les méthodes HTTP standard sont utilisées pour les différentes opérations.
====

=== Format des requêtes

* Content-Type: application/json
* Authentification via token Bearer
* Filtrage et tri disponibles
* Pagination automatique

[NOTE.speaker]
====
Les requêtes et réponses sont en JSON.
L'authentification se fait via un token JWT.
Il est possible de filtrer et trier les résultats via des paramètres dans l'URL.
La pagination est gérée automatiquement avec les paramètres page et perPage.
====

// tag::demo[]
=== Démonstration

**Utilisation de l'API REST**

[NOTE.speaker]
====
* Utiliser curl pour tester l'API :

```bash
# Liste des posts
curl http://127.0.0.1:8090/api/collections/posts/records

# Création d'un post
curl -X POST http://127.0.0.1:8090/api/collections/posts/records \
  -H "Content-Type: application/json" \
  -d '{"title": "Mon premier post", "content": "Hello World"}'

# Récupération d'un post spécifique
curl http://127.0.0.1:8090/api/collections/posts/records/RECORD_ID

# Mise à jour d'un post
curl -X PATCH http://127.0.0.1:8090/api/collections/posts/records/RECORD_ID \
  -H "Content-Type: application/json" \
  -d '{"title": "Titre modifié"}'
```

* Montrer les réponses JSON
