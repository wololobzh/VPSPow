== Introduction à la réactivité

* Un système qui réagit automatiquement aux changements
* Comme un domino qui en fait tomber d'autres
* L'interface utilisateur se met à jour toute seule
* Basée sur un système de déclarations réactives avec les "runes"

[NOTE.speaker]
====
Utiliser ces analogies pour expliquer la réactivité :
* Le thermostat qui réagit à la température
* Une feuille de calcul Excel qui met à jour les totaux
* Un réseau social qui actualise le nombre de likes

Faire une petite démonstration avec Excel pour montrer la réactivité en action
====

=== La réactivité en action

* L'interface utilisateur réagit automatiquement aux changements d'état
* Plus besoin de manipuler directement le DOM
* Performance optimisée car seules les parties nécessaires sont mises à jour

[NOTE.speaker]
====
* Montrer un exemple simple de compteur qui s'incrémente
* Expliquer que Svelte s'occupe de toute la synchronisation
* Insister sur la simplicité du code par rapport à une approche manuelle
====

**Création d'un compteur réactif simple**

[NOTE.speaker]

* Ajouter un état count avec $state
* Créer un bouton qui incrémente le compteur
* Montrer que l'interface se met à jour automatiquement

```svelte
<script>
  let count = $state(0);
```

== État réactif avec $state

=== Déclaration d'un état

* Utilisation de la rune `$state()`
* Transforme une variable en état réactif
* Peut contenir des types primitifs ou des objets complexes

[NOTE.speaker]
====
* $state est la base de la réactivité dans Svelte 5
* La syntaxe est simple mais puissante
* L'état peut être modifié par réassignation ou mutation
====

=== État profond (Deep reactivity)

* Les objets et tableaux sont réactifs en profondeur
* Les modifications de propriétés déclenchent des mises à jour
* Utilisation de méthodes comme push(), pop(), etc.

[NOTE.speaker]
====
* La réactivité profonde est automatique
* Pas besoin de spread operator ou de clonage
* Les proxies JavaScript sont utilisés en interne
====

**Manipulation d'états profonds**

[NOTE.speaker]
====
* Créer un tableau réactif
* Montrer différentes façons de le modifier
* Observer les mises à jour automatiques

```svelte
<script>
  let numbers = $state([1, 2, 3]);
  
  function addNumber() {
    numbers.push(numbers.length + 1);
```

== Inspection et débogage

=== Outils d'inspection

* `$state.snapshot()` pour obtenir une copie non-réactive
* `$inspect` pour suivre les changements d'état
* Console de développement pour le débogage

[NOTE.speaker]
====
* Les états réactifs ne peuvent pas être directement loggués
* $state.snapshot crée une copie safe pour le logging
* $inspect est automatiquement retiré en production
====

// tag::demo[]
=== Démonstration

**Utilisation des outils d'inspection**

[NOTE.speaker]
====
* Montrer comment inspecter un état réactif
* Utiliser les différentes méthodes de logging

```svelte
<script>
  let counter = $state({ value: 0 });
  
  $inspect(counter);
  
  function increment() {
    counter.value++;
    console.log($state.snapshot(counter));
  }
</script>
```
====

== Introduction aux effets

* Un effet est une action qui se déclenche automatiquement quand un état change
* Comparable à un observateur qui surveille et réagit aux changements
* Utile pour synchroniser des états ou effectuer des actions secondaires

[NOTE.speaker]
====
* Utiliser l'analogie d'un surveillant qui réagit à des événements
* Exemple : comme un parent qui réagirait quand son enfant pleure
* Les effets sont comme des "recettes" qui s'exécutent automatiquement quand les ingrédients (états) changent
====

=== Cas d'utilisation courants

* Mise à jour du titre de la page
* Sauvegarde automatique des données
* Animations basées sur des changements d'état
* Appels API en réaction à des changements

=== Démonstration

**Effet simple : titre de page dynamique**

[NOTE.speaker]
====
* Créer un effet qui met à jour le titre de la page

```svelte
<script>
  let pageTitle = $state("Accueil");
  
  // L'effet se déclenche chaque fois que pageTitle change
  $effect(() => {

  });
</script>

<input 
  type="text" 
  bind:value={pageTitle} 
  placeholder="Changez le titre"
/>
```

== État partagé : le concept

* Parfois, plusieurs composants ont besoin des mêmes données
* L'état partagé permet de centraliser ces données
* Comme un "tableau d'affichage" visible par tous

[NOTE.speaker]
====
* Utiliser l'analogie d'un tableau d'affichage dans une école
* Tous les élèves peuvent voir les informations
* Quand le tableau change, tout le monde voit la mise à jour
====

=== Organisation du code partagé

* Création d'un fichier spécial avec extension `.svelte.js`
* Contient les états partagés entre composants
* Comme une "base de données" locale pour notre application

// tag::demo[]

== Exercice

* Créer un composant Todo List avec les fonctionnalités suivantes:
** Une liste de tâches réactive
** Possibilité d'ajouter une nouvelle tâche
** Possibilité de marquer une tâche comme terminée
** Un compteur du nombre de tâches restantes

[NOTE.speaker]
====
Solution attendue :

```svelte
<script>
  let todos = $state([]);
  
  function addTodo(text) {
    todos.push({ text, done: false });
  }
  
  function toggleTodo(index) {
    todos[index].done = !todos[index].done;
  }
  
  $effect(() => {
    console.log('Tâches restantes:', todos.filter(t => !t.done).length);
  });
</script>
```
