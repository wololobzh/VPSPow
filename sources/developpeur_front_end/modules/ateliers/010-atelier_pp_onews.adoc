== Déroulé de l'atelier

=== 1. Fiche récapitulative de Pair Programming

[NOTE.speaker]
====
Commencez par présenter une fiche récapitulative des bonnes pratiques du pair programming.

**Rappel :**  
Le pair programming consiste à alterner les rôles entre le **driver** (celui qui code) et le **navigator** (celui qui réfléchit et guide).

Exemple d'organisation :
- **Driver :** écrit le code.
- **Navigator :** analyse, repère les erreurs potentielles, propose des solutions.

Changer de rôle **toutes les 20-30 minutes**.
====

=== 2. Live Share en collaboration

[NOTE.speaker]
====
1. **Un seul clone du projet !**  
   L'un des binômes clone le dépôt et héberge la session **Live Share**.

2. **Comment partager la session Live Share :**  
   - Lancer Live Share dans VS Code.  
   - Envoyer le lien d'invitation à votre binôme.  

3. **Partager le dépôt GitHub avec le binôme :**  
   - Aller sur GitHub.  
   - Sélectionner "Settings" > "Manage Access".  
   - Inviter votre binôme.
====

=== 3. Création des salles Discord

1. **Afficher le fichier avec les groupes.**  
2. Chaque groupe crée une salle vocale sur Discord et l'ajoute au document partagé.

=== 4. Accéder au localhost de son binôme

Pour visualiser le localhost de votre binôme, utilisez le VPN.

- Accédez au lien suivant :  
  **http://vpncheck.lan/**  
  Vérifiez que votre binôme est connecté avec son identifiant : **prenom-nom**.

== Règles à suivre pendant l'atelier

=== 1. Gestion des problèmes techniques

[NOTE.speaker]
====
Si vous avez un **problème technique** :  
- Postez dans le canal **#sav** ou **#entraide** sur Slack.

Si vous avez un **problème de code** :  
- Testez des solutions.  
- Si cela prend plus de **15 minutes sans solution**, créez une **issue** sur le dépôt.  

⚠️ **Pas de messages privés aux formateurs !**  
Les formateurs passent régulièrement voir les groupes.
====

=== 2. Bonnes pratiques de commit

[NOTE.speaker]
====
1. **Commitez régulièrement !**  
   Chaque changement de codeur doit être accompagné d'un commit.

2. **Push sur GitHub fréquemment.**

3. **Les sondages** :  
   Des sondages seront réalisés durant la journée pour suivre votre avancement.
====

=== 3. Pause repas

La **pause repas** doit être prise entre **12h et 13h**.  
⚠️ **Ne laissez pas votre binôme seul.**

La fin de l'atelier est prévue à **17h**. Si vous terminez plus tôt, explorez des **bonus** comme :  
- Ajout de **transitions/animations**.  
- Travail sur d'autres **révisions**.

== Rappels techniques pendant l'atelier

[NOTE.speaker]
====
**Points à vérifier pendant votre travail :**

1. **Unités CSS :**  
   - %  
   - vw, vh  

2. **Images :**  
   - Utilisez `background-image` et ajustez la taille avec `background-size`.  

3. **Positionnement des blocs :**  
   - Utilisez `display: inline` ou `flexbox` pour positionner deux blocs côte à côte.

4. **Formats d'images :**  
   - **.svg** : format vectoriel léger et adapté aux logos.  

5. **Structure HTML :**  
   - Où placer le `header` et le `main` ?

6. **Validation HTML :**  
   - Utilisez le **W3C Validator** pour valider votre HTML :  
     https://validator.w3.org/

7. **Inclure des balises :**  
   - Consultez **Can I Include** pour savoir quelles balises peuvent être imbriquées les unes dans les autres.
====
