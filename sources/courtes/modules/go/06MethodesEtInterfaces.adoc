== Méthodes

Une méthode est une fonction associée à un type :

[source,go]
----
type Rectangle struct {
    Largeur, Hauteur float64
}

// Méthode avec récepteur valeur
func (r Rectangle) Surface() float64 {
    return r.Largeur * r.Hauteur
}

// Méthode avec récepteur pointeur
func (r *Rectangle) Redimensionner(facteur float64) {
    r.Largeur *= facteur
    r.Hauteur *= facteur
}
----

[NOTE.speaker]
--
Les méthodes peuvent être définies sur n'importe quel type nommé.
Le récepteur apparaît avant le nom de la méthode.
Le choix entre récepteur valeur et pointeur est important.
Les méthodes sont appelées avec la notation point.
--

    fmt.Printf("Surface après agrandissement: %.2f\n", c.Surface())
}
```

== Interfaces

Une interface définit un ensemble de méthodes :

[source,go]
----
type Forme interface {
    Surface() float64
    Perimetre() float64
}

type Rectangle struct {
    Largeur, Hauteur float64
}

// Rectangle implémente automatiquement Forme
func (r Rectangle) Surface() float64 {
    return r.Largeur * r.Hauteur
}

func (r Rectangle) Perimetre() float64 {
    return 2 * (r.Largeur + r.Hauteur)
}
----

[NOTE.speaker]
--
L'implémentation est implicite en Go.
Pas besoin de déclarer explicitement l'implémentation.
Une interface peut être implémentée par plusieurs types.
Les interfaces doivent être petites et focalisées.
--

== Interfaces Communes

Go définit plusieurs interfaces standard :

[source,go]
----
// Interface Stringer pour représentation string
type Stringer interface {
    String() string
}

// Interface error pour la gestion d'erreurs
type error interface {
    Error() string
}

// Interface io.Reader pour la lecture
type Reader interface {
    Read(p []byte) (n int, err error)
}
----

[NOTE.speaker]
--
fmt.Stringer est utilisée pour l'affichage personnalisé.
error est fondamentale pour la gestion d'erreurs.
io.Reader et io.Writer sont très utilisées pour l'I/O.
--

package main

import "fmt"

type Personne struct {
    Nom string
    Age int
}

func (p Personne) String() string {
    return fmt.Sprintf("%s (%d ans)", p.Nom, p.Age)
}

type Animal struct {
    Espece string
    Age    int
}

func (a Animal) String() string {
    return fmt.Sprintf("%s de %d ans", a.Espece, a.Age)
}

func afficher(s fmt.Stringer) {
    fmt.Println(s.String())
}

func main() {
    p := Personne{"Alice", 30}
    a := Animal{"Chat", 5}
    
    afficher(p)
    afficher(a)
}
```
3. Expliquer l'interface Stringer
4. Montrer le polymorphisme via l'interface

== Composition

Go favorise la composition plutôt que l'héritage :

[source,go]
----
type Animal struct {
    Nom string
    Age int
}

type Chat struct {
    Animal  // Embedding
    Griffes bool
}

// Les méthodes de Animal sont promues à Chat
func (a Animal) Description() string {
    return fmt.Sprintf("%s (%d ans)", a.Nom, a.Age)
}
----

[NOTE.speaker]
--
L'embedding permet la promotion de champs et méthodes.
Plus flexible que l'héritage classique.
Permet de composer des comportements.
Favorise la réutilisation de code.
--
