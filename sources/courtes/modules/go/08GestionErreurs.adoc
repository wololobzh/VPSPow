== Interface error

L'interface error est fondamentale en Go :

[source,go]
----
type error interface {
    Error() string
}
----

* Type intégré simple
* Retournée comme valeur additionnelle
* Peut être enrichie avec du contexte

[NOTE.speaker]
--
L'interface error est volontairement simple.
Convention : dernier retour d'une fonction.
Permet de créer des types d'erreurs personnalisés.
nil indique l'absence d'erreur.
--

```go
package main

import (
    "fmt"
)

type ValidationError struct {
    Field string
    Issue string
}

func (e *ValidationError) Error() string {
    return fmt.Sprintf("validation failed on %s: %s", e.Field, e.Issue)
}

func validateAge(age int) error {
    if age < 0 {
        return &ValidationError{
            Field: "age",
            Issue: "cannot be negative",
        }
    }
    if age > 150 {
        return &ValidationError{
            Field: "age",
            Issue: "seems unrealistic",
        }
    }
    return nil
}

func main() {
    ages := []int{-5, 25, 200}
    for _, age := range ages {
        if err := validateAge(age); err != nil {
            fmt.Printf("Error: %v\n", err)
        } else {
            fmt.Printf("Age %d is valid\n", age)
        }
    }
}
```

== Panic

Panic est utilisé pour les erreurs irrécupérables :

* Arrête l'exécution normale
* Déclenche les fonctions defer
* Propage l'erreur dans la stack

[source,go]
----
func division(a, b int) int {
    if b == 0 {
        panic("division par zéro")
    }
    return a / b
}
----

[NOTE.speaker]
--
Panic doit être utilisé avec parcimonie.
Préférer le retour d'erreur quand possible.
Utile pour les erreurs de programmation.
Souvent utilisé pendant l'initialisation.
--

== Recover

Recover permet de reprendre le contrôle après un panic :

* Fonctionne uniquement dans une fonction defer
* Retourne la valeur passée à panic
* Permet de nettoyer avant de terminer

[source,go]
----
func handlePanic() {
    if r := recover(); r != nil {
        fmt.Printf("Recovered from: %v\n", r)
    }
}

func riskyFunction() {
    defer handlePanic()
    panic("something went wrong")
}
----

[NOTE.speaker]
--
Recover est souvent utilisé avec defer.
Permet de logger les erreurs avant de terminer.
Utile pour les serveurs et les goroutines.
--

```go
func processWork(id int) {
    defer func() {
        if r := recover(); r != nil {
            log.Printf("Recovered in work %d: %v", id, r)

        panic(fmt.Sprintf("simulated panic in work %d", id))

}

func main() {
    for i := 1; i <= 3; i++ {
        fmt.Printf("Starting work %d\n", i)
        processWork(i)
    }

}
```

== Patterns de Gestion d'Erreurs

Bonnes pratiques pour la gestion d'erreurs :

* Erreurs avec contexte
* Wrapping d'erreurs
* Vérification de type d'erreur

[source,go]
----
type QueryError struct {
    Query string
    Err   error
}

func (e *QueryError) Error() string {
    return fmt.Sprintf("query %q failed: %v", e.Query, e.Err)
}

func (e *QueryError) Unwrap() error {
    return e.Err
}
----

[NOTE.speaker]
--
Ajouter du contexte aux erreurs.
Utiliser le wrapping pour la chaîne d'erreurs.
Permettre l'inspection des erreurs sous-jacentes.
--
