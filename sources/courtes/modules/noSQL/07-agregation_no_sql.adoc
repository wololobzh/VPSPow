== Qu’est-ce que l’agrégation en NoSQL ?

L’agrégation est un mécanisme permettant d’analyser et transformer les données grâce à des opérations successives.
Elle remplace généralement :

* les `JOIN` complexes,
* les `GROUP BY`,
* les calculs intermédiaires (somme, moyenne, comptage…),
* les transformations de structure,
* les filtrages avancés.

[NOTE.speaker]
--
Dans le NoSQL (et surtout MongoDB), l’agrégation est un **pipeline** : une suite d’étapes où la sortie de l’une devient l’entrée de la suivante, ce qui permet de construire des traitements puissants et modulaires.
--

== Le pipeline d’agrégation

Un pipeline d’agrégation est une liste d’opérations successives :

```
db.collection.aggregate([
  { étape 1 },
  { étape 2 },
  { étape 3 }
])
```

Chaque étape utilise un opérateur commençant par `$`.

[NOTE.speaker]
--
L’idée est d’enchaîner plusieurs transformations, comme dans une usine de traitement de données.
Chaque étape doit être pensée pour être la plus sélective possible, afin d’optimiser les performances.
--

== Les étapes essentielles du pipeline

Les étapes principales sont :

* `$match` : filtrer
* `$project` : sélectionner et transformer les champs
* `$group` : regrouper et agréger
* `$sort` : trier
* `$limit` et `$skip` : paginer
* `$unwind` : éclater un tableau
* `$lookup` : joindre (équivalent d’un JOIN)
* `$addFields` : ajouter de nouveaux champs

[NOTE.speaker]
--
Ces opérateurs couvrent l’essentiel des besoins d’analyse. Leur combinaison permet de remplacer des requêtes SQL très complexes.
--

== Exemple simple : filtrer et trier

```
db.users.aggregate([
  { $match: { age: { $gte: 18 } } },
  { $sort: { age: 1 } }
])
```

[NOTE.speaker]
--
Le pipeline filtre d’abord, puis trie.
Toujours filtrer avant de trier pour limiter la quantité de données manipulées.
--

== $project : sélectionner et transformer les champs

Exemple :

```
db.users.aggregate([
  { $project: { _id: 0, name: 1, age: 1 } }
])
```

Transformations possibles :

```
{ $project: { name: 1, isAdult: { $gte: ["$age", 18] } } }
```

[NOTE.speaker]
--
`$project` permet de remodeler la structure des données. On peut créer de nouveaux champs, supprimer des champs et formater les valeurs.
--

== $group : regrouper et calculer

Exemple : compter le nombre d’utilisateurs par rôle :

```
db.users.aggregate([
  { $group: { _id: "$role", count: { $sum: 1 } } }
])
```

Opérateurs courants :

* `$sum` : somme ou comptage (avec 1)
* `$avg` : moyenne
* `$min` / `$max`
* `$push` : ajouter une valeur dans un tableau

[NOTE.speaker]
--
`_id` dans `$group` est la valeur par laquelle on regroupe.
Chaque groupe devient un document dans le résultat final.
--

== Exemple : statistiques avancées

```
db.orders.aggregate([
  { $match: { status: "completed" } },
  { $group: {
      _id: "$customerId",
      totalSpent: { $sum: "$amount" },
      avgOrder: { $avg: "$amount" },
      orderCount: { $sum: 1 }
  }}
])
```

[NOTE.speaker]
--
Très utile dans les applications e-commerce, SaaS, analyse clients…
--

== $unwind : éclater un tableau

Si un document contient un tableau, `$unwind` crée un document par élément du tableau.

Exemple :

```
{
  name: "Alice",
  hobbies: ["music", "coding", "gaming"]
}
```

```
db.users.aggregate([
  { $unwind: "$hobbies" }
])
```

Résultat : 3 documents (un par hobby).

[NOTE.speaker]
--
Très pratique pour analyser des données stockées sous forme de listes.
--

== $lookup : faire un JOIN

MongoDB permet une jointure simple :

```
db.orders.aggregate([
  { $lookup: {
      from: "users",
      localField: "userId",
      foreignField: "_id",
      as: "user"
  }}
])
```

[NOTE.speaker]
--
Contrairement à SQL, les résultats de `$lookup` sont intégrés sous forme de tableau.
Il est parfois conseillé de dénormaliser plutôt que de multiplier les JOIN.
--

== Pipeline complet : un vrai exemple

Objectif : afficher les 5 utilisateurs qui ont dépensé le plus.

```
db.orders.aggregate([
  { $match: { status: "completed" } },
  { $group: { _id: "$userId", total: { $sum: "$amount" } } },
  { $sort: { total: -1 } },
  { $limit: 5 },
  { $lookup: {
      from: "users",
      localField: "_id",
      foreignField: "_id",
      as: "user"
  }},
  { $unwind: "$user" },
  { $project: {
      _id: 0,
      name: "$user.name",
      total: 1
  }}
])
```

[NOTE.speaker]
--
Ce pipeline combine : filtrage → regroupement → tri → pagination → jointure → projection.
C’est le type d’analyse réalisé dans les dashboards, KPI, statistiques internes…
--

== Quand utiliser l’agrégation ?

L’agrégation est idéale pour :

* produire des statistiques
* analyser de grands volumes de données
* transformer des documents en de nouvelles structures
* éviter les traitements lourds dans le code applicatif

[NOTE.speaker]
--
L’agrégation est souvent plus rapide qu’un traitement côté serveur applicatif.
Elle utilise les capacités du moteur de base de données, optimisées pour les calculs.
--

== Limitations de l’agrégation

* Performances limitées si les filtres ne sont pas indexés
* Une pipeline trop complexe peut devenir difficile à maintenir
* `$lookup` est assez coûteux (équivalent d'un JOIN)
* Certaines opérations sont limitées en environnement shardé

[NOTE.speaker]
--
Bien modéliser les données reste essentiel pour éviter de dépendre d’un pipeline trop long ou trop coûteux.
--

== Conclusion
// tag::conclusion[]
* L’agrégation en NoSQL permet de transformer et analyser efficacement vos données.
* Le pipeline est puissant grâce à des opérateurs comme `$match`, `$group`, `$project`, `$lookup`, `$unwind`.
* Une bonne compréhension des étapes permet d’optimiser les performances.
* L’agrégation est un outil indispensable pour la création de dashboards, métriques et analyses avancées.
// end::conclusion[]
