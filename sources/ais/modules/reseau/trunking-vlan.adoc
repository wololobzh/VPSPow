== Le trunking

Le **trunking** permet de faire transiter plusieurs VLANs sur un seul lien physique entre des switches ou entre un switch et un routeur.

=== VLAN Tagging (802.1Q) 

Les trames sur un lien trunk sont "taggées" pour indiquer de quel VLAN elles proviennent. Ce marquage est effectué à l’aide du protocole IEEE 802.1Q.

=== Port en mode Trunk 

* Un port trunk permet de transporter le trafic de plusieurs VLANs sur un même lien physique.
* **Cas d’usage** : Utilisé principalement pour la communication entre switches ou entre un switch et un routeur, où plusieurs VLANs doivent traverser un seul lien.

=== Tagging des trames :

* Les trames Ethernet sont taggées lorsqu'elles traversent un lien trunk. Chaque trame est marquée avec un identifiant VLAN qui permet aux switches de savoir à quel VLAN elle appartient.
* **802.1Q Standard** : Le protocole 802.1Q ajoute un champ de 4 octets dans l’en-tête de la trame Ethernet qui contient l’ID VLAN.

== Configuration d’un lien trunk

**Étape 1** :  Sélectionner le port à configurer en mode trunk

```sh
Switch(config)# interface fastethernet 0/24
```

=> Sélectionne le port FastEthernet 0/24.

**Étape 2** :  Configurer le port en mode trunk

```sh
Switch(config-if)# switchport mode trunk
```

=> Configure le port pour transporter le trafic de plusieurs VLANs (trunking).

include::../../../../adoc/libs/slide-notitle.adoc[]

**Étape 3** :  Spécifier quels VLANs peuvent transiter sur ce lien trunk

```sh
Switch(config-if)# switchport trunk allowed vlan 10,20,30
```

=> Autorise uniquement les VLANs 10, 20, et 30 à traverser ce lien trunk.

include::../../../../adoc/libs/slide-notitle.adoc[]

**Étape 4** :  Configurer un VLAN natif (non tagué)

```sh
Switch(config-if)# switchport trunk native vlan 99
```

=> Spécifie le VLAN 99 comme VLAN natif pour les trames non taguées.

== Routage inter-VLAN

**Problématique : **

Les VLANs, par conception, ne peuvent pas communiquer entre eux directement. 

Cela signifie qu’un périphérique sur le VLAN 10 ne peut pas envoyer de paquets à un périphérique sur le VLAN 20 sans intervention.

**Solution :** 

Pour permettre cette communication, un routeur ou un switch de niveau 3 est nécessaire pour router le trafic entre les VLANs.  C’est ce qu’on appelle le **routage inter-VLAN**.

=== Configuration du Routage inter-VLAN 

**Étape 1** : Accéder à l’interface du routeur

```sh
Router(config)# interface gigabitEthernet 0/0
```

=> Création d'une sous-interface pour le VLAN 10 sur le port GigabitEthernet 0/0.

**Étape 2 **: Créer une sous-interface pour le VLAN 10

```sh
Router(config-subif)# encapsulation dot1Q 10
```

=> Active l’encapsulation 802.1Q pour le VLAN 10.

```sh
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
```

=> Attribue une adresse IP à la sous-interface pour permettre le routage inter-VLAN.

include::../../../../adoc/libs/slide-notitle.adoc[]

**Étape 3** : Répéter le processus pour les autres VLANs (20 et 30)

**Étape 4** : Vérification de la configuration

```sh
Router# show ip interface brief
```

=> Cette commande affiche un tableau récapitulatif de toutes les interfaces et sous-interfaces sur le routeur, avec leurs adresses IP et leur statut.

== Démonstration

[NOTE.speaker]
--
configurer le routage inter-VLAN sur un routeur, voici un exemple complet en suivant les étapes que vous avez mentionnées pour les VLANs 10, 20 et 30.

**Étape 1 : Accéder à l’interface du routeur**

```sh
Router> enable
Router#configure terminal 
```

Entrez en mode de configuration de l'interface principale :

```sh
Router(config)# interface gigabitEthernet 0/0
```

**Étape 2 : Créer une sous-interface pour chaque VLAN**

Vous allez configurer une sous-interface pour chaque VLAN et lui attribuer une adresse IP unique. Voici comment configurer les sous-interfaces pour les VLANs 10, 20, et 30.

Configuration pour le VLAN 10 :

```sh
Router(config)# interface gigabitEthernet 0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
```

Configuration pour le VLAN 20 :

```sh
Router(config)# interface gigabitEthernet 0/0.20
Router(config-subif)# encapsulation dot1Q 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0
```

Configuration pour le VLAN 30 :

```sh
Router(config)# interface gigabitEthernet 0/0.30
Router(config-subif)# encapsulation dot1Q 30
Router(config-subif)# ip address 192.168.30.1 255.255.255.0
```

Chaque sous-interface est maintenant configurée pour effectuer le routage entre les VLANs 10, 20 et 30.

**Étape 4 : Vérification de la configuration**

Pour vérifier la configuration des interfaces et s'assurer que chaque sous-interface est correctement configurée, utilisez la commande :

```sh
Router# show ip interface brief
```

Cela affichera une liste de toutes les interfaces (y compris les sous-interfaces) avec leurs adresses IP et leur état, permettant de confirmer que le routage inter-VLAN est bien en place.

== Conclusion
// tag::conclusion[]
Domaine de Diffusion et de Collision :

* Les VLANs créent des domaines de diffusion indépendants, limitant la propagation de trames et augmentant les performances réseau.

Ports en mode Access et Trunk :

* Mode Access : Un port appartient à un seul VLAN.
* Mode Trunk : Transporte plusieurs VLANs en taggant les trames

Configuration des VLANs :

* Création et nommage des VLANs, assignation de ports en mode access, et vérification des associations via show vlan brief.

include::../../../../adoc/libs/slide-notitle.adoc[]

Trunking et Routage inter-VLAN :

* Le trunking (802.1Q) permet à plusieurs VLANs de circuler sur un seul lien physique.
* Le routage inter-VLAN, routeur ou switch de niveau 3, nécessaire pour la communication entre VLANs

Sécurité des VLANs :

* Prévenir le VLAN hopping en limitant les VLANs autorisés sur les trunks et en désactivant les trunks inutilisés.
* ACL et politiques spécifiques pour renforcer le contrôle d’accès entre VLANs.

// end::conclusion[]
