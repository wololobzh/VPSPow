== Automatisation ?

L'automatisation en Bash consiste à écrire des scripts qui exécutent automatiquement des tâches répétitives ou complexes sans intervention manuelle. 

include::../../../../adoc/libs/slide-notitle.adoc[]

Cela permet de :

* Gagner du temps : Automatiser les tâches répétitives permet aux administrateurs système de se concentrer sur des tâches plus complexes et créatives, tout en laissant les scripts s'occuper des tâches routinières.
* Réduire les erreurs humaines : Les scripts exécutent les mêmes instructions de manière cohérente, réduisant ainsi le risque d'erreurs dues à des manipulations manuelles.
* Assurer la cohérence : Les tâches automatisées sont exécutées de manière uniforme, garantissant des résultats constants et fiables.

Les scripts d'automatisation sont largement utilisés pour la gestion des systèmes, la surveillance, les sauvegardes, et bien d'autres tâches.

== Exemples de commande automatisable 

=== Sauvegardes Automatiques

Les scripts de sauvegarde sont utilisés pour copier des fichiers ou des répertoires importants afin de les protéger contre la perte de données.

**Exemple :**

```sh
#!/bin/bash
# Sauvegarder un répertoire vers un fichier tar.gz
tar -czvf /chemin/vers/sauvegarde.tar.gz /chemin/vers/dossier
Explication :
tar -czvf : Crée une archive compressée (gzip) avec des fichiers listés.
/chemin/vers/sauvegarde.tar.gz : Chemin et nom du fichier de sauvegarde.
/chemin/vers/dossier : Répertoire à sauvegarder.
```

=== Nettoyage de Répertoires

Les scripts de nettoyage automatisent la suppression des fichiers inutiles ou obsolètes pour libérer de l'espace disque.

**Exemple :**

```sh
#!/bin/bash
# Supprimer les fichiers de plus de 30 jours
find /chemin/vers/dossier -type f -mtime +30 -exec rm {} \;
```

[NOTE.speaker]
--
**Explication :**

* `find /chemin/vers/dossier` : Recherche dans le répertoire spécifié.
* `-type f` : Recherche uniquement des fichiers.
* `-mtime +30` : Sélectionne les fichiers modifiés il y a plus de 30 jours.
* `-exec rm {} \;` : Exécute la commande de suppression sur chaque fichier trouvé.
--

=== Surveillance des Logs

Les scripts de surveillance surveillent les fichiers de logs pour détecter des événements spécifiques ou des erreurs.

**Exemple :**

```sh
#!/bin/bash
# Surveiller les nouvelles entrées de type erreur dans syslog
tail -f /var/log/syslog | grep --line-buffered -i "error\|err\|fail\|crit\|alert\|emerg"
```
[NOTE.speaker]
--
**Explication :**

* `tail -f /var/log/syslog` : Affiche en temps réel les nouvelles lignes ajoutées au fichier `syslog`.
* `grep --line-buffered` : Cette option permet à grep de traiter l'entrée ligne par ligne, même lorsqu'il est utilisé dans un pipe. Cela garantit que les résultats sont affichés en temps réel.
* `-i` : Cette option permet de rendre la recherche insensible à la casse, ce qui signifie que `grep` trouvera à la fois `error` et `Error`.
* `"error\|err\|fail\|crit\|alert\|emerg"` : Cette expression régulière recherche plusieurs termes couramment utilisés pour désigner des erreurs 
--

== Planification avec cron

`cron` est un démon Unix qui permet de planifier l'exécution de scripts et de commandes à des intervalles réguliers spécifiques. 

La planification est définie dans des fichiers appelés crontab, et chaque ligne de ces fichiers spécifie une tâche à exécuter et le moment de son exécution.

=== Structure de crontab

* Le fichier crontab contient une liste de tâches à exécuter, chaque tâche étant définie par une ligne. 
* Chaque ligne comporte cinq champs de spécification temporelle suivis de la commande à exécuter.
* Les cinq champs indiquent respectivement la minute, l'heure, le jour du mois, le mois et le jour de la semaine.

=== Syntaxe de crontab

```sh
* * * * * commande
```

* **Minute** (0-59) : Indique à quelle minute l'exécution doit avoir lieu.
* **Heure** (0-23) : Indique à quelle heure l'exécution doit avoir lieu.
* **Jour du mois** (1-31) : Spécifie le jour du mois.
* **Mois** (1-12 ou noms abrégés comme jan, feb, etc.) : Spécifie le mois de l'année.
* **Jour de la semaine** (0-7, 0 ou 7 représentant dimanche) : Spécifie le jour de la semaine.
* **Commande** : La commande ou le script à exécuter.

Les valeurs * dans les champs indiquent une correspondance avec toutes les valeurs possibles pour ce champ.

=== Exemple d'Entrées dans `crontab`

**Exemple 1 :**

```sh
0 2 * * * /chemin/vers/script.sh
```

**Explication** : Exécute `script.sh` chaque jour à 2h00 du matin.

**Exemple 2 :**

```sh
30 1 15 * * /chemin/vers/rapport_mensuel.sh
```

**Explication** : Exécute rapport_mensuel.sh le 15 de chaque mois à 1h30.

=== Variables Spéciales et Utilitaires

**Variables Spéciales**

* MAILTO : Spécifie l'adresse e-mail à laquelle envoyer les sorties de cron (`stdout` et `stderr`).
** **Exemple** : `MAILTO=utilisateur@example.com`
** Si cette variable est définie, les résultats de l'exécution de la tâche seront envoyés par e-mail à l'adresse spécifiée.

=== Créer ou Éditer le crontab de l'utilisateur :

```sh
crontab -e
```

Ouvre le fichier `crontab` de l'utilisateur courant dans l'éditeur de texte par défaut, permettant de créer ou de modifier les tâches planifiées.

=== Afficher les Tâches Planifiées :

```sh
crontab -l
```

Liste toutes les tâches planifiées pour l'utilisateur courant.

=== Supprimer le crontab de l'utilisateur :

```sh
crontab -r
```

Supprime toutes les tâches planifiées pour l'utilisateur courant.

=== Restaurer un crontab :

```sh
crontab fichier
```

Cette commande charge les tâches planifiées à partir d'un fichier spécifié.

== Planification avec anacron

**anacron** utilitaire complémentaire à **cron** 

Gère l'exécution des tâches planifiées là où le système peut ne pas être en fonctionnement continu contrairement à **cron** où le système doit être en marche 

**anacron** garantit que les tâches planifiées seront exécutées même si le système était éteint ou non disponible au moment prévu.

=== Fonctionnement :

* exécute des tâches régulièrement, mais sans se baser sur une planification stricte mais sur des périodes de temps écoulées (jours, semaines, mois)
* Lors du démarrage du système, **anacron** vérifie les tâches qui auraient dû être exécutées pendant l'arrêt du système et les exécute dès que possible.

=== Exemple d'utilisation :

```sh
/etc/anacrontab
```

Le fichier **anacrontab** contient les tâches à exécuter, similaires au fichier **crontab**, mais avec une syntaxe adaptée à anacron. Un exemple d'entrée dans **anacrontab** pourrait ressembler à ceci :

```sh
1  5  backup.daily  /scripts/sauvegarde.sh
```

* `1` : Période en jours (1 jour dans cet exemple).
* `5` : Délai maximal en minutes avant l'exécution de la tâche après le démarrage.
* `backup.daily` : Identifiant de la tâche.
* `/scripts/sauvegarde.sh` : Commande ou script à exécuter.

=== Usage typique : 

**anacron** est utile sur les systèmes qui ne sont pas allumés en permanence, comme les ordinateurs portables.

Il garantit que les tâches critiques, comme les sauvegardes, sont exécutées même si le système n'était pas en fonctionnement à l'heure prévue par **cron**.

== Planification avec at

**at** permet de planifier l'exécution d'une tâche à un moment précis dans le futur. 

Contrairement à **cron**, qui est utilisé pour les tâches répétitives, at est conçu pour des exécutions ponctuelles. 

Une fois la tâche exécutée, elle est supprimée de la file d'attente.

=== Exemple d'utilisation :

```sh
echo "sh /scripts/nettoyage.sh" | at 03:30
```

* Exécution du script `nettoyage.sh` à 3h30 du matin. 
* Commande envoyée à **at** via le pipe (|)

=== Syntaxe de la commande `at` :

* **at** suivi de l'heure et de la date pour exécuter une commande.
* Les formats d'heure et de date peuvent inclure :
** Heure : `HH:MM` (24 heures) ou `HHam/HHpm`
** Date : `MMDDYY, MM/DD/YY, now + time`
** Mots clés relatifs : `now, midnight, noon, teatime`

=== Créer une tâche:

```sh
echo "sh /scripts/nettoyage.sh" | at 10:15 PM tomorrow
```

Cela planifie l'exécution de la commande saisie à 10h15 le lendemain.

=== Voir les tâches planifiées :

La commande **atq** permet d’afficher la liste des tâches planifiées.

=== Annuler une tâche planifiée : 

La commande `atrm + ID de la tâche` permet de supprimer une tâche planifiée.

**at** est pratique pour les tâches qui doivent être exécutées une seule fois à un moment spécifique, comme l'envoi d'un rappel, l'exécution d'un script de nettoyage ou de maintenance, ou tout autre processus qui ne nécessite pas de répétition.

== Démonstration

[NOTE.speaker]
--
**Exemples de commandes automatisables**

**Commandes :**

* Sauvegarde : Créer une archive tar compressée des fichiers importants.
* Nettoyage : Supprimer les fichiers temporaires de plus de 7 jours.
* Envoi de rapport : Envoyer un e-mail contenant un rapport journalier.

**Script à créer** : `backup_cleanup_report.sh`

**Étape 1 : Créer le script Bash**

```sh
nano ~/backup_cleanup_report.sh
```

**Étape 2 : Ajouter les commandes suivantes dans le script**

```sh
#!/bin/bash

# Sauvegarde des fichiers importants
tar -czf /backup/backup_$(date +%F).tar.gz /important_files

# Nettoyage des fichiers temporaires de plus de 7 jours
find /tmp -type f -mtime +7 -exec rm {} \;

# Envoi du rapport quotidien par e-mail
mail -s "Rapport quotidien" admin@example.com < /var/log/report.log
```

**Étape 3 : Sauvegarder et quitter**

Appuyer sur Ctrl + X, puis Y, puis Entrée.

**Étape 4 : Rendre le script exécutable**

```sh
chmod +x ~/backup_cleanup_report.sh
```

* **Planification avec cron**

**Objectif** : Planifier l'exécution du script tous les jours à 2h00 du matin.

**Étape 1 : Ouvrir l'éditeur crontab**

```sh
crontab -e
```

**Étape 2 : Ajouter la ligne suivante à la fin du fichier**

```sh
0 2 * * * /home/user/backup_cleanup_report.sh
```

(Remplacer `/home/user/` par le chemin approprié)

**Étape 3 : Sauvegarder et quitter**

Appuyer sur Ctrl + X, puis Y, puis Entrée.

* **Gestion de crontab**

**Objectif** : Comprendre comment gérer les tâches cron d’un utilisateur.

**Étape 1 : Lister les tâches cron**

```sh
crontab -l
```

**Étape 2 : Modifier une tâche cron**

Refaire la commande `crontab -e`, puis ajouter ou modifier les entrées nécessaires.

**Étape 3 : Supprimer toutes les tâches cron**

```sh
crontab -r
```

**Attention** : Cette commande supprimera toutes les tâches cron pour l'utilisateur.

* **Planification avec anacron**

**Objectif** : Utiliser anacron pour les tâches qui doivent être exécutées même si la machine est éteinte à l’heure prévue.

**Étape 1 : Modifier le fichier anacrontab**

```sh
sudo nano /etc/anacrontab
```

**Étape 2 : Ajouter la ligne suivante pour une tâche quotidienne**

```sh
1 5 backup.daily /home/user/backup_cleanup_report.sh
```

(Remplacer `/home/user/` par le chemin approprié)

**Étape 3 : Sauvegarder et quitter**

Appuyer sur Ctrl + X, puis Y, puis Entrée.

* **Planification avec at**

**Objectif** : Planifier une tâche unique, par exemple, envoyer un rapport à 17h30 aujourd'hui.

**Étape 1 : Planifier la tâche avec at**

```sh
echo "mail -s 'Rapport exceptionnel' admin@example.com < /var/log/report.log" | at 17:30
```

**Étape 2 : Lister les tâches at en attente**

```sh
atq
```

**Étape 3 : Supprimer une tâche at (si nécessaire)**

```sh
atrm <job_id>
```

(Remplacer `<job_id>` par l'identifiant de la tâche à supprimer)
