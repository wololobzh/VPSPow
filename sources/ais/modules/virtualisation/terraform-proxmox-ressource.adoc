== Machines virtuelles

**Ressource `proxmox_virtual_environment_vm`**

* https://registry.terraform.io/providers/bpg/proxmox/latest/docs/resources/virtual_environment_vm[documentation de la ressource]

=== Démonstration

Création d'une machine virtuelle Proxmox avec Terraform.

[NOTE.speaker]
--
* Partons sur un exemple simple de ressource. Bien observer les commentaires dans cet exemple, on reviendra sur les détails ensuite

* Penser à ajouter un ISO Ubuntu 22.04 dans le datastore local pour l'installation de la VM

```hcl
resource "proxmox_virtual_environment_vm" "ubuntu_vm" {
  // Nom de la VM pour identification dans Proxmox
  name        = "simple-ubuntu-vm"
  // Description de la VM, utile pour la documentation ou les commentaires
  description = "Managed by Terraform"
  // Tags pour catégoriser ou filtrer les VMs dans Proxmox
  tags        = ["terraform", "ubuntu"]

  // Nom du nœud Proxmox sur lequel déployer la VM
  node_name = "first-node"
  // Identifiant unique de la VM, doit être unique sur le nœud
  vm_id     = 4321

  // Configuration de l'agent QEMU (désactivé ici)
  agent {
    enabled = false  // Garder désactivé si l'agent QEMU n'est pas configuré dans la VM
  }

  // Comportement lors de la destruction de la VM
  stop_on_destroy = true  // Arrête la VM au lieu de l'éteindre lors de la destruction

  // Configuration de démarrage de la VM
  startup {
    order      = "3"   // Ordre de démarrage dans la séquence des VM
    up_delay   = "60"  // Délai en secondes avant le démarrage
    down_delay = "60"  // Délai en secondes avant l'arrêt suivant
  }

  // Configuration CPU de la VM
  cpu {
    cores = 2  // Nombre de cœurs CPU alloués à la VM
    type  = "x86-64-v2-AES"  // Type de CPU émulé, adapté aux processeurs modernes
  }

  // Configuration mémoire de la VM
  memory {
    dedicated = 2048  // Mémoire allouée en MB
    floating  = 2048  // Activer le ballon de mémoire, ici égal à dedicated
  }

  // Configuration du disque principal de la VM
  disk {
    datastore_id = "local-lvm"  // Datastore où le disque est stocké
    file_id      = "local:iso/ubuntu-22.04-server-cloudimg-amd64.img"  // Fichier ISO pour l'installation
    interface    = "scsi0"  // Interface du disque, ici SCSI
  }

  // Configuration d'initialisation de la VM
  initialization {
    ip_config {
      ipv4 {
        address = "dhcp"  // Utilisation de DHCP pour l'adresse IP
      }
    }

    user_account {
      // Informations de l'utilisateur initial
      password = "securepassword123"  // Mot de passe de l'utilisateur
      username = "ubuntu"  // Nom de l'utilisateur
    }
  }

  // Configuration de l'interface réseau de la VM
  network_device {
    bridge = "vmbr0"  // Pont réseau utilisé pour la connectivité
  }

  // Type de système d'exploitation de la VM
  operating_system {
    type = "l26"  // Indique un OS basé sur le noyau Linux 2.6 à 5.X
  }

  // Configuration de l'état TPM pour la sécurité
  tpm_state {
    version = "v2.0"  // Version TPM utilisée pour la VM
  }

  // Ajout d'un périphérique série, utile pour la console série
  serial_device {}
}
```

* Planifier puis exécuter le déploiement de la VM

**Explications additionnelles**

* **Nom et Description**: Utilisés pour identifier et documenter la VM dans Proxmox.
* **Agent QEMU**: Important pour des fonctionnalités avancées comme le redémarrage à distance, mais doit être configuré dans la VM pour être activé.
* **Démarrage et Arrêt**: Le stop_on_destroy assure que la VM est proprement arrêtée.
* **CPU et Mémoire**: Les paramètres doivent être ajustés selon les besoins de l'application exécutée sur la VM.
* **Disque**: La spécification du fichier ISO est essentielle pour l'installation de l'OS.
* **Initialisation**: La configuration initiale avec DHCP et un compte utilisateur permet une mise en service rapide.
* **Réseau**: La configuration par défaut permet une connectivité réseau de base.
* **TPM et Périphériques**: Optionnels mais utiles pour des besoins spécifiques en sécurité et en gestion.
--

* nécessite l'accès SSH au node Proxmox

// tag::demo[]

=== Démonstration

Création d'un conteneur LXC Proxmox avec Terraform.

[NOTE.speaker]
--
* Les conteneurs LXC sont une alternative légère aux machines virtuelles pour les applications isolées.

* D'abord il faut créer un template qui sera utilisé pour le conteneur. Pour cela on peut faire appel aux templates officiels de Proxmox ou créer un template personnalisé.

* Voici un exemple de configuration pour un conteneur LXC :

```hcl
resource "proxmox_virtual_environment_container" "ubuntu_container" {
  // Description du conteneur, utile pour la documentation ou les commentaires
  description = "Managed by Terraform"

  // Nom du nœud Proxmox où le conteneur sera déployé
  node_name = "first-node"
  // Identifiant unique du conteneur, doit être unique sur le nœud
  vm_id     = 1234

  // Configuration d'initialisation du conteneur
  initialization {
    // Nom d'hôte du conteneur
    hostname = "terraform-provider-proxmox-ubuntu-container"

    ip_config {
      ipv4 {
        address = "dhcp"  // Utilisation de DHCP pour l'adresse IP
      }
    }

    user_account {
      // Informations de compte utilisateur pour l'accès SSH
      keys = [
        // Clé SSH publique pour l'accès sécurisé
        "ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQC7..."
      ]
      password = "securepassword123"  // Mot de passe de l'utilisateur root
    }
  }

  // Configuration de l'interface réseau du conteneur
  network_interface {
    name = "veth0"  // Nom de l'interface réseau virtuelle
  }

  // Configuration du système d'exploitation du conteneur
  operating_system {
    // Identifiant du fichier modèle pour l'OS
    template_file_id = "local:vztmpl/ubuntu-22.04-standard.tar.gz"
    type             = "ubuntu"  // Type de système d'exploitation
  }

  // Points de montage pour le conteneur
  mount_point {
    // Montage d'un volume lié, nécessite l'authentification root@pam
    volume = "/mnt/bindmounts/shared"
    path   = "/mnt/shared"
  }

  mount_point {
    // Création d'un nouveau volume par PVE
    volume = "local-lvm"
    size   = "10G"  // Taille du volume
    path   = "/mnt/volume"  // Chemin d'accès dans le conteneur
  }

  // Comportement de démarrage du conteneur
  startup {
    order      = "3"   // Ordre de démarrage dans la séquence des conteneurs
    up_delay   = "60"  // Délai en secondes avant le démarrage
    down_delay = "60"  // Délai en secondes avant l'arrêt suivant
  }
}
```

* Planifier et exécuter le déploiement du conteneur LXC

**Explications Additionnelles**

* **Nom et Description**: Utilisés pour identifier et documenter le conteneur dans Proxmox.
* **Initialisation**: Configuration initiale avec DHCP pour la connectivité réseau et des clés SSH pour un accès sécurisé.
* **Réseau**: L'interface réseau veth0 est utilisée pour la connectivité.
* **Système d'Exploitation**: Utilisation d'un modèle Ubuntu pour la création du conteneur.
* **Points de Montage**: Permet de monter des volumes liés et de créer de nouveaux volumes pour le stockage.
* **Démarrage et Arrêt**: Le comportement de démarrage est configuré pour s'assurer que le conteneur démarre et s'arrête proprement.

== Stockages

Pour une VM ou un conteneur donné, il est possible de spécifier le stockage utilisé.

* https://registry.terraform.io/providers/bpg/proxmox/latest/docs/resources/virtual_environment_vm#example-attached-disks[documentation des disques attachés sur VM]
* il est possible également d'utiliser l'argument `disk` dans le cas des conteneurs
* les disques peuvent être attachés à un stockage local ou partagé

=== Exemple de configuration

```hcl
resource "proxmox_virtual_environment_vm" "data_vm" {
  // Nom du nœud Proxmox où la VM est hébergée
  node_name = "first-node"
  // La VM n'est jamais démarrée
  started = false
  // Ne démarre pas automatiquement au boot du nœud
  on_boot = false

  // Premier disque de données
  disk {
    datastore_id = "local-zfs"  // Datastore où le disque est stocké
    file_format  = "raw"        // Format du fichier de disque
    interface    = "scsi0"      // Interface SCSI
    size         = 1            // Taille en Go
  }

  // Deuxième disque de données
  disk {
    datastore_id = "local-zfs"
    file_format  = "raw"
    interface    = "scsi1"
    size         = 4
  }
}
```

=== Pare-feu

* on peut définir des règles de pare-feu pour les VMs et les conteneurs

```hcl
// Activer le pare-feu au niveau du cluster
resource "proxmox_virtual_environment_cluster_firewall" "example_firewall" {
  enabled = true  // Active le pare-feu pour l'ensemble du cluster
}

// Configuration d'un alias de pare-feu pour faciliter la gestion des adresses IP
resource "proxmox_virtual_environment_firewall_alias" "trusted_networks" {
  name        = "trusted_networks"
  description = "Réseaux de confiance"
  cidr        = ["192.168.1.0/24", "192.168.2.0/24"]  // Réseaux autorisés
}

// Définition d'un ensemble d'IP pour les adresses IP bannies
resource "proxmox_virtual_environment_firewall_ipset" "banned_ips" {
  name = "banned_ips"
  entries = [
    "203.0.113.0/24",  // Exemple d'une plage d'IP bannies
    "198.51.100.0/24"
  ]
}

// Configuration des règles de pare-feu
resource "proxmox_virtual_environment_firewall_rules" "example_rules" {
  // Règle pour autoriser le trafic SSH depuis les réseaux de confiance
  rule {
    type        = "in"
    action      = "accept"
    source      = "@trusted_networks"
    dest        = "0.0.0.0/0"
    macro       = "ssh"
    description = "Autoriser SSH depuis les réseaux de confiance"
  }

  // Règle pour bloquer le trafic depuis les IP bannies
  rule {
    type        = "in"
    action      = "drop"
    source      = "@banned_ips"
    dest        = "0.0.0.0/0"
    description = "Bloquer le trafic depuis les IP bannies"
  }

  // Règle pour autoriser le HTTP et HTTPS
  rule {
    type        = "in"
    action      = "accept"
    source      = "0.0.0.0/0"
    dest        = "0.0.0.0/0"
    macro       = "http"
    description = "Autoriser HTTP"
  }

  rule {
    type        = "in"
    action      = "accept"
    source      = "0.0.0.0/0"
    dest        = "0.0.0.0/0"
    macro       = "https"
    description = "Autoriser HTTPS"
  }

  // Règle par défaut pour refuser tout autre trafic entrant
  rule {
    type        = "in"
    action      = "drop"
    source      = "0.0.0.0/0"
    dest        = "0.0.0.0/0"
    description = "Refuser tout autre trafic entrant"
  }
}
```

[NOTE.speaker]
--
**Explications des Composants**

* **Cluster Firewall Activation**:
** Active le pare-feu au niveau du cluster pour sécuriser l'ensemble de l'infrastructure.
* **Firewall Alias**:
** Crée un alias pour les réseaux de confiance, simplifiant la gestion des règles.
* **IP Set**:
** Définit un ensemble d'IP pour les adresses bannies, permettant de bloquer facilement le trafic indésirable.
* **Firewall Rules**:
** SSH Access: Autorise uniquement le trafic SSH provenant des réseaux de confiance.
** Blocked IPs: Bloque le trafic provenant des adresses IP bannies.
** HTTP/HTTPS Access: Autorise le trafic HTTP et HTTPS pour tout le monde, assurant l'accessibilité des services web.
** Default Deny: Refuse tout autre trafic entrant pour renforcer la sécurité par défaut.
--

=== DNS

```hcl
// Configuration DNS pour le cluster Proxmox
resource "proxmox_virtual_environment_dns" "example_dns" {
  // Liste des serveurs DNS à utiliser
  servers = [
    "8.8.8.8",      // Serveur DNS public de Google
    "8.8.4.4",      // Serveur DNS secondaire de Google
    "1.1.1.1"       // Serveur DNS de Cloudflare
  ]

  // Domaine de recherche par défaut
  search = [
    "example.com",  // Domaine principal
    "internal.local" // Domaine interne pour la résolution de noms locaux
  ]

  // Options supplémentaires (optionnel)
  domain = "example.com" // Domaine par défaut pour les requêtes DNS
}
```

[NOTE.speaker]
--
**Explications des Composants**

* **Serveurs DNS** :
** `servers` : Spécifie une liste de serveurs DNS pour la résolution de noms. Dans cet exemple, nous utilisons les serveurs publics de Google et Cloudflare, qui sont réputés pour leur rapidité et leur fiabilité.
* **Domaines de Recherche** :
** `search` : Définit les domaines de recherche par défaut. Lorsqu'un nom de domaine partiel est utilisé, ces domaines sont ajoutés pour tenter de résoudre le nom complet. Par exemple, si vous recherchez "server1", le système tentera "server1.example.com" et "server1.internal.local".
* **Domaine (Optionnel)** :
** `domain` : Spécifie le domaine par défaut pour les requêtes DNS. Cela peut être utilisé pour définir un domaine principal pour l'environnement, simplifiant la gestion des noms de domaine et la résolution dans les configurations locales.

**Utilisation et Avantages**

* **Centralisation de la Configuration DNS** : En définissant les serveurs DNS et les domaines de recherche au niveau du cluster, vous assurez une configuration cohérente et facile à gérer pour toutes les machines virtuelles et conteneurs.
* **Flexibilité et Fiabilité** : En utilisant des serveurs DNS de différents fournisseurs (Google, Cloudflare), vous améliorez la résilience et la disponibilité du service DNS dans votre environnement.
--

=== Bridge

```hcl
// Configuration d'un bridge réseau Linux sur un nœud Proxmox
resource "proxmox_virtual_environment_network_linux_bridge" "example_bridge" {
  // Nom du nœud Proxmox où le bridge sera configuré
  node_name = "node1"

  // Nom du bridge réseau
  name = "vmbr1"

  // Configuration de l'adresse IP statique du bridge
  ip_address = "192.168.100.1"
  netmask    = 24  // Masque de sous-réseau pour l'adresse IP

  // Optionnel : Passerelle par défaut pour le bridge
  gateway = "192.168.100.254"

  // Optionnel : Activer ou désactiver le bridge
  enabled = true  // Active le bridge

  // Optionnel : Définir le MTU (Maximum Transmission Unit)
  mtu = 1500  // Valeur standard pour Ethernet

  // Optionnel : Activer le Spanning Tree Protocol (STP)
  stp = false  // Désactive STP, peut être activé si nécessaire

  // Optionnel : Définir le délai d'attente du bridge
  bridge_ports = ["eth0"]  // Associe le bridge à l'interface physique eth0
}
```

[NOTE.speaker]
--
**Explications des Composants**

* **Nom du Nœud** :
** `node_name` : Spécifie sur quel nœud Proxmox le bridge sera configuré. Cela permet de gérer les configurations réseau de manière spécifique à chaque hôte.
* **Nom du Bridge** :
** `name` : Définit le nom du bridge réseau, ici "vmbr1". Ce nom est utilisé pour référencer le bridge dans d'autres configurations réseau.
* **Configuration IP** :
** `ip_address` et `netmask` : Attribuent une adresse IP statique et un masque de sous-réseau au bridge, permettant aux machines virtuelles de communiquer via ce bridge.
* **Passerelle** :
** `gateway` : Définir une passerelle par défaut permet au bridge de diriger le trafic vers d'autres réseaux.
* **Options de Bridge** :
** enabled : Permet d'activer ou de désactiver le bridge.
** mtu : Spécifie la taille maximale des paquets qui peuvent être transmis. La valeur par défaut pour Ethernet est 1500.
** stp : Le Spanning Tree Protocol peut être activé pour prévenir les boucles réseau dans des configurations complexes.
* **Ports du Bridge** :
** `bridge_ports` : Associe le bridge à une ou plusieurs interfaces réseau physiques, ici "eth0", permettant aux VMs et conteneurs de partager l'accès réseau via le bridge.

**Utilisation et Avantages**

* **Facilite la Communication** : Les bridges permettent aux VMs et conteneurs de communiquer entre eux et avec des réseaux externes.
* **Flexibilité** : En configurant les options comme le MTU et le STP, vous pouvez adapter le bridge à différentes topologies réseau et besoins de performance.
* **Simplicité** : Une configuration centralisée et cohérente des bridges facilite la gestion de l'infrastructure réseau dans un environnement virtualisé.

=== VLAN

```hcl
// Configuration d'un VLAN sur un nœud Proxmox
resource "proxmox_virtual_environment_network_linux_vlan" "example_vlan" {
  // Nom du nœud Proxmox où le VLAN sera configuré
  node_name = "node1"

  // Nom de l'interface VLAN
  name = "vlan100"

  // ID du VLAN
  vlan_id = 100

  // Interface parent (pont réseau)
  bridge = "vmbr1"

  // Optionnel : Configuration IP statique du VLAN
  ip_address = "192.168.101.1"
  netmask    = 24  // Masque de sous-réseau pour l'adresse IP

  // Optionnel : Passerelle par défaut pour le VLAN
  gateway = "192.168.101.254"

  // Optionnel : Activer ou désactiver le VLAN
  enabled = true  // Active le VLAN

  // Optionnel : Définir le MTU (Maximum Transmission Unit)
  mtu = 1500  // Valeur standard pour Ethernet
}
```

[NOTE.speaker]
--
**Explications des Composants**

* **Nom du Nœud** :
** `node_name` : Indique sur quel nœud Proxmox le VLAN sera configuré. Cela permet de spécifier la configuration VLAN pour chaque hôte de manière distincte.
* **Nom de l'Interface VLAN** :
** `name` : Définit le nom de l'interface VLAN, ici "vlan100". Ce nom est utilisé pour identifier le VLAN dans les configurations réseau.
* **ID du VLAN** :
** `vlan_id` : Spécifie l'identifiant unique du VLAN, qui est utilisé pour taguer le trafic réseau appartenant à ce VLAN.
* **Bridge** :
** `bridge` : Associe le VLAN à un bridge réseau existant, ici "vmbr1", permettant au VLAN de segmenter le trafic sur ce bridge.
* **Configuration IP** :
** `ip_address` et `netmask` : Attribuent une adresse IP statique et un masque de sous-réseau au VLAN, permettant aux machines virtuelles de communiquer via ce VLAN.
* **Passerelle** :
** `gateway` : Définit une passerelle par défaut pour diriger le trafic du VLAN vers d'autres réseaux.
* **Options du VLAN** :
** `enabled` : Permet d'activer ou de désactiver le VLAN.
** `mtu` : Spécifie la taille maximale des paquets qui peuvent être transmis, généralement 1500 pour Ethernet.

**Utilisation et Avantages**

* **Segmentation du Réseau** : Les VLANs permettent de segmenter le réseau pour isoler le trafic, améliorer la sécurité et gérer plus efficacement les ressources réseau.
* **Optimisation de la Performance** : En séparant le trafic en VLANs, vous pouvez réduire la congestion et améliorer les performances réseau.
* **Flexibilité** : La configuration des VLANs permet de s'adapter aux besoins spécifiques de différentes applications ou départements au sein de l'organisation.
