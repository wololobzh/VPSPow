== Introduction

* Les runners locaux sont utilisés pour exécuter des jobs CI/CD sur votre propre infrastructure
* Ils offrent plus de contrôle et flexibilité par rapport aux runners hébergés

https://docs.github.com/en/actions/hosting-your-own-runners/managing-self-hosted-runners/about-self-hosted-runners[Documentation GitHub Actions - Runners locaux]

[NOTE.speaker]
--
Les runners locaux vous permettent d'exécuter vos workflows CI/CD sur vos propres serveurs. Cela vous donne un contrôle total sur l'environnement d'exécution, y compris les configurations matérielles et logicielles.

Ils sont particulièrement utiles pour les projets nécessitant des ressources spécifiques ou des configurations de sécurité avancées.
--

== Concepts clés

* Un runner local est un agent qui exécute des jobs depuis votre propre machine
* Nécessite une configuration initiale et des ressources matérielles adéquates

[NOTE.speaker]
--
Un runner local est un programme qui s'exécute sur votre machine pour traiter les jobs définis dans vos workflows CI/CD. Il peut être configuré pour utiliser des ressources spécifiques et s'adapter à des environnements particuliers.

Assurez-vous que votre machine répond aux exigences matérielles et logicielles nécessaires pour exécuter les jobs efficacement.
--

== Avantages

* Plus de contrôle sur l'environnement d'exécution
* Réduction potentielle des coûts si vous disposez déjà de l'infrastructure
* Personnalisation accrue des outils et bibliothèques installés

[NOTE.speaker]
--
Utiliser un runner local vous permet de personnaliser entièrement votre environnement d'exécution. Vous pouvez installer des outils et des bibliothèques spécifiques qui ne sont pas disponibles sur les runners hébergés.

Cela peut également réduire les coûts, car vous utilisez votre propre infrastructure au lieu de payer pour des services hébergés.
--

== Étapes de mise en place

. Téléchargement et installation du runner local
. Configuration des permissions et accès nécessaires
. Enregistrement du runner avec votre dépôt
. Modification des workflows pour utiliser le runner `self-hosted`

https://docs.github.com/en/actions/hosting-your-own-runners/managing-self-hosted-runners/adding-self-hosted-runners?learn=hosting_your_own_runners&learnProduct=actions[Documentation GitHub Actions - Ajouter un runner local]

[NOTE.speaker]
--
Pour mettre en place un runner local, téléchargez d'abord le programme d'installation à partir de votre plateforme CI/CD. Suivez les instructions pour l'installer sur votre machine.

Configurez ensuite les permissions nécessaires pour que le runner puisse accéder à votre dépôt. Enfin, enregistrez le runner avec votre dépôt pour qu'il puisse recevoir et exécuter les jobs.
--
