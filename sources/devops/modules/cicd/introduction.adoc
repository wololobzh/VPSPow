== Introduction

* CI/CD signifie Intégration Continue / Déploiement Continu
* Processus clé dans le développement logiciel moderne
* Automatisation des tests et des déploiements

image::assets/cicd.png[]

[NOTE.speaker]
--
La CI/CD est un ensemble de pratiques qui permet de livrer du code de manière plus rapide et sécurisée. L'intégration continue se focalise sur le test automatique du code à chaque modification. Le déploiement continu vise à automatiser le déploiement des applications. Ces pratiques réduisent les erreurs humaines et accélèrent le temps de mise sur le marché.
--

== Avantages

* Accélération du développement
* Amélioration de la qualité du code
* Réduction du risque de déploiement

[NOTE.speaker]
--
Les pipelines CI/CD permettent de livrer du code plus rapidement tout en assurant une meilleure qualité grâce à des tests automatisés. Ils réduisent le risque d'erreurs lors des déploiements en automatisant les processus et en rendant les déploiements répétitifs et prévisibles.
--

== Cas d'usage

* Automatisation des tests unitaires et d'intégration
* Déploiements fréquents et fiables
* Mise à jour continue des environnements de développement et de production

[NOTE.speaker]
--
Les pipelines CI/CD sont utilisés pour automatiser les tests, ce qui permet de détecter les erreurs tôt dans le cycle de développement. Ils permettent des déploiements fréquents et fiables, facilitant ainsi les mises à jour continues et les corrections de bugs. Cela est particulièrement avantageux pour les équipes qui pratiquent le développement agile.
--

== Outils CI/CD courants

* Jenkins, GitLab CI, CircleCI, Travis CI...
* Focus sur l'utilisation de GitHub Actions dans les futurs modules

[NOTE.speaker]
--
Il existe plusieurs outils pour mettre en place des pipelines CI/CD. 

* Jenkins est un outil très populaire et flexible. 
* GitLab CI est bien intégré à la plateforme GitLab. 
* CircleCI et Travis CI sont également largement utilisés. 

Dans les futurs modules, nous nous concentrerons sur GitHub Actions, qui est directement intégré à GitHub et offre une grande simplicité d'utilisation pour les projets hébergés sur cette plateforme.
--

=== Github Actions

* Intégré à GitHub
* Utilisation de workflows YAML
* Déclenchement sur des événements Git

=== Exemple de workflow Github Actions

[source,yaml]
----
name: Node.js CI

on:
  push:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout repository
      uses: actions/checkout@v2

    - name: Set up Node.js
      uses: actions/setup-node@v2
      with:
        node-version: '14'

    - name: Install dependencies
      run: npm install

    - name: Run tests
      run: npm test
----

[NOTE.speaker]
--
Ce workflow s'appelle "Node.js CI" et s'exécute sur chaque push vers la branche main. Il s'exécute sur un environnement Ubuntu.

Les étapes incluent le checkout du code source, la configuration de Node.js à la version 14, l'installation des dépendances via npm install, et l'exécution des tests définis dans votre projet avec npm test.
--

=== Gitlab CI

* Intégré à GitLab
* Utilisation de fichiers YAML
* Déclenchement sur des événements Git

=== Exemple de fichier .gitlab-ci.yml

[source,yaml]
----
stages:
  - test

variables:
  NODE_ENV: test
  NODE_VERSION: "14"

before_script:
  - apt-get update -qq && apt-get install -y -qq curl
  - curl -sL https://deb.nodesource.com/setup_$NODE_VERSION.x | bash -
  - apt-get install -y nodejs
  - npm install

test_job:
  stage: test
  script:
    - npm test
  only:
    - main
----

[NOTE.speaker]
--
Ce fichier .gitlab-ci.yml définit un pipeline avec une étape test. Les variables NODE_ENV et NODE_VERSION sont définies pour configurer l'environnement et la version de Node.js.

Dans before_script, les paquets nécessaires sont installés et Node.js est configuré.

Le job test_job exécute npm test pour lancer les tests. Il s'exécute uniquement sur la branche main.
--
