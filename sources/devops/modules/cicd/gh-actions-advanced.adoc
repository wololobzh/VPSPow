== Introduction

* Fonctionnalités avancées de GitHub Actions pour des workflows CI/CD complexes
* Importance de ces fonctionnalités pour améliorer l'efficacité et la flexibilité des pipelines

[NOTE.speaker]
--
Les fonctionnalités avancées de GitHub Actions permettent de créer des workflows plus complexes, ce qui est crucial pour les projets nécessitant une CI/CD robuste.

Comprendre ces concepts vous aidera à optimiser vos pipelines en termes de temps et de ressources.
--

== Concepts clés

* **Multi-job** : Permet l'exécution parallèle et séquentielle de plusieurs jobs
* **Matrices** : Paramétrage dynamique pour exécuter des jobs avec différentes configurations
* **Dépendances** : Gestion des relations entre jobs pour contrôler l'ordre d'exécution

[NOTE.speaker]
--
Le concept de multi-job vous permet de définir plusieurs jobs dans un même workflow, qui peuvent s'exécuter en parallèle ou en séquence selon vos besoins.

Les matrices sont utilisées pour exécuter un même job avec différentes configurations, comme plusieurs versions d'un langage ou différents systèmes d'exploitation.

Les dépendances entre jobs vous permettent de gérer l'ordre d'exécution, assurant ainsi que certains jobs ne commencent qu'une fois leurs dépendances terminées.
--

== Démonstration 1

Configuration d'un workflow multi-job s'exécutant en parallèle et en séquence

[NOTE.speaker]
--
Nous allons configurer un workflow GitHub Actions avec plusieurs jobs :

1. Créez un fichier `.github/workflows/multi-job.yml`.
2. Ajoutez deux jobs : un job de build et un job de test.
3. Configurez le job de test pour qu'il dépende du job de build.
4. Lancer le worklow pour observer l'exécution des jobs en parallèle et en séquence.
5. Supprimez le `needs` puis relancer le workflow pour observer la différence.

Exemple de fichier YAML :

```yaml
name: Multi-Job Workflow

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
    - name: Check out code
      uses: actions/checkout@v2
    - name: Build
      run: echo "Building the project..."

  test:
    runs-on: ubuntu-latest
    needs: build
    steps:
    - name: Run tests
      run: echo "Running tests..."
```
--
// end::demo[]

== Avantages

* Réduction du temps d'exécution grâce au parallélisme
* Flexibilité et réutilisation des workflows
* Meilleure gestion des ressources avec les dépendances

[NOTE.speaker]
--
L'utilisation de plusieurs jobs et de matrices peut réduire considérablement le temps total d'exécution d'un workflow en tirant parti de l'exécution parallèle.

Cela offre également une grande flexibilité, car vous pouvez réutiliser des configurations de jobs pour différents environnements ou scénarios de test.

Les dépendances vous permettent d'optimiser l'utilisation des ressources en veillant à ce que les jobs soient exécutés dans le bon ordre.
--

// tag::demo[]
== Démonstration 2

Utilisation des matrices dans un workflow pour tester différentes combinaisons de versions de langages et de systèmes d'exploitation

[NOTE.speaker]
--
Nous allons créer un workflow utilisant une matrice pour tester notre application sur plusieurs versions de Node.js et d'Ubuntu :

1. Modifiez le fichier `.github/workflows/multi-job.yml`.
2. Ajoutez une matrice au job de test pour inclure plusieurs versions de Node.js et d'Ubuntu.

Exemple de fichier YAML :

```yaml
name: Matrix Workflow

on:
  push:
    branches:
      - main

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [12, 14, 16]
        os: [ubuntu-latest, ubuntu-20.04]
    steps:
    - name: Check out code
      uses: actions/checkout@v2
    - name: Setup Node.js
      uses: actions/setup-node@v2
      with:
        node-version: ${{ matrix.node }}
    - name: Run tests
      run: echo "Running tests on Node.js ${{ matrix.node }} and OS ${{ matrix.os }}..."
```
--
// end::demo[]

== Bonnes pratiques

* Optimisation des jobs pour réduire les temps d'attente
* Utilisation des matrices pour maximiser la couverture des tests
* Gestion efficace des dépendances pour éviter les erreurs d'exécution

[NOTE.speaker]
--
Pour tirer le meilleur parti des fonctionnalités avancées de GitHub Actions, optimisez vos jobs en réduisant les tâches inutiles et en utilisant le cache quand c'est possible.

Les matrices permettent de maximiser la couverture des tests en testant plusieurs configurations avec le même code.

Assurez-vous que les dépendances entre jobs sont bien définies pour éviter les erreurs d'exécution dues à des dépendances non satisfaites.
--

== Exercice

Concevoir un workflow avec des jobs dépendants pour *simuler* un pipeline lint puis test puis build.

[NOTE.speaker]
--
```yaml
name: Dependent Jobs Workflow

on:
  push:
    branches:
      - main

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
    - name: Run linter
      run: echo "Linting the code..."

  test:
    runs-on: ubuntu-latest
    needs: lint
    steps:
    - name: Run tests
      run: echo "Running tests..."

  build:
    runs-on: ubuntu-latest
    needs: test
    steps:
    - name: Build
      run: echo "Building the project..."
```
