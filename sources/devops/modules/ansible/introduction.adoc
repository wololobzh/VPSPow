== Introduction à Ansible

* **Définition** : Ansible est un outil open-source pour l'automatisation des tâches IT, la gestion des configurations et l'orchestration.
* **Architecture** :
  ** Agentless : fonctionne sans installation d'agents sur les nœuds cibles
  ** Utilise SSH pour la communication
  ** Basé sur des fichiers YAML appelés playbooks

[NOTE.speaker]
--
Ansible simplifie l'automatisation des tâches grâce à sa nature agentless. Il utilise des fichiers YAML pour décrire les tâches à exécuter, ce qui le rend facile à lire et à écrire.
--

=== Comparaison avec d'autres outils

* **Puppet/Chef** : nécessitent des agents installés sur les nœuds
* **Terraform** : plus orienté infrastructure as code

[NOTE.speaker]
--
Ansible se distingue par sa simplicité d'utilisation et son absence d'agents, ce qui facilite son déploiement. Il est complémentaire à d'autres outils comme Terraform qui se concentre sur la gestion d'infrastructure.
--

== Cas d'utilisation d'Ansible

* **Automatisation des tâches IT** : déploiement de logiciels, configurations système
* **Gestion des configurations** : assurer la conformité des systèmes
* **Déploiement d'applications** : orchestrer le déploiement sur plusieurs serveurs
* **Orchestration** : coordination de services multi-niveaux

[NOTE.speaker]
--
Ansible est utilisé pour automatiser des tâches répétitives, gérer des configurations complexes, et déployer des applications de manière orchestrée. Cela permet de gagner du temps et de réduire les erreurs humaines.
--

== Avantages d'Ansible

* **Simplicité et rapidité** : facile à apprendre, syntaxe claire
* **Agentless** : réduit la complexité de gestion des nœuds
* **Extensibilité** : nombreux modules disponibles pour étendre ses capacités
* **Communauté active** : support et contributions régulières

[NOTE.speaker]
--
Ansible est apprécié pour sa simplicité et son modèle agentless qui facilite son adoption. Sa communauté active contribue à l'amélioration continue de l'outil et au développement de nouveaux modules.
--

== Concepts fondamentaux

* **Playbooks** : fichiers YAML décrivant les tâches à exécuter
* **Inventaires** : listes de nœuds sur lesquels exécuter les tâches
* **Modules** : outils pour effectuer des actions sur les nœuds
* **Tasks** : actions à effectuer sur les nœuds
* **Rôles** : regroupements de tâches et de fichiers pour une fonctionnalité spécifique
* **Handlers** : actions déclenchées par des événements
* **Facts** : informations sur les nœuds

[NOTE.speaker]
--
* *Playbooks* : Des fichiers écrits en YAML qui définissent l'ensemble des tâches à exécuter sur les nœuds. Ils décrivent "quoi" exécuter et "comment" le faire.
* *Inventaire* : Un fichier ou une source dynamique qui répertorie tous les nœuds (hôtes) sur lesquels Ansible doit opérer. Il peut inclure des groupes pour organiser les nœuds.
* *Modules* : Des unités de code qui effectuent les tâches spécifiques mentionnées dans les playbooks. Ansible propose de nombreux modules pour gérer les fichiers, les packages, les services, etc.
* *Tasks* : Des actions individuelles définies dans un playbook qui utilisent des modules pour accomplir des tâches spécifiques.
* *Roles* : Une manière structurée d'organiser des playbooks, des tâches, des fichiers, des variables, et des templates pour réutiliser et partager la configuration.
* *Handlers* : Des tâches qui ne s'exécutent que si elles sont notifiées par d'autres tâches, typiquement utilisées pour gérer les changements de configuration nécessitant un redémarrage de service.
* *Facts* : Des informations collectées automatiquement par Ansible sur les nœuds, telles que les adresses IP, le système d'exploitation, la mémoire, etc., qui peuvent être utilisées pour prendre des décisions conditionnelles.
--

== Aperçu de la syntaxe

=== Playbook

Un exemple simple de playbook Ansible :

```yaml
---
- hosts: webservers
  tasks:
    - name: Update package repository
      apt:
        update_cache: yes

    - name: Install Apache
      apt:
        name: apache2
        state: present
```

=== Module

```yaml
- name: Install Apache
    apt:
    name: apache2
    state: present
```

* Indépendance : chaque module est conçu pour être autonome
* Etat idempotent : exécutable plusieurs fois sans effet
* Déclaratif : spécifie "quoi" faire, pas "comment"

[NOTE.speaker]
--
Un module dans Ansible est une unité de code qui exécute une tâche spécifique sur les nœuds cibles. Les modules sont au cœur du fonctionnement d'Ansible, car ils définissent les actions à réaliser, comme installer un package, copier un fichier, ou gérer un service.

* *Indépendance* : Chaque module est conçu pour être autonome et effectuer une tâche précise. Cela signifie que vous pouvez appeler un module sans dépendre d'autres modules.
* *État Idempotent* : Les modules Ansible sont conçus pour être idempotents, ce qui signifie que les exécuter plusieurs fois produira le même résultat sans affecter l'état du système. Par exemple, si vous utilisez un module pour installer un package, il vérifiera d'abord si le package est déjà installé avant de procéder.
* *Langage* : Les modules peuvent être écrits dans n'importe quel langage de programmation, mais sont souvent développés en Python pour tirer parti de l'écosystème Python et de ses bibliothèques.
* *Exécution* : Lorsqu'un playbook est exécuté, Ansible envoie les modules nécessaires aux nœuds cibles, les exécute, et récupère les résultats. Ansible utilise généralement SSH pour établir la connexion et exécuter les modules sur les nœuds.
* *Paramètres* : Les modules acceptent des paramètres qui spécifient comment la tâche doit être effectuée. Par exemple, le module apt pour gérer les packages sur les systèmes Debian peut accepter des paramètres pour définir quel package installer et dans quelle version.
* *Retour d'Information* : Après exécution, les modules renvoient des informations à Ansible, notamment si la tâche a été modifiée, réussie ou échouée, ainsi que tout message de retour pertinent.
--

=== Inventory

Fichier ou une source dynamique qui répertorie tous les nœuds sur lesquels Ansible doit exécuter des tâches.

```ini
[webservers]
web1.example.com
98.246.2.45

[dbservers]
db1.example.com
db2.example.com
```

[NOTE.speaker]
--
* *Format* : Par défaut, l'inventaire est un fichier texte, généralement nommé inventory ou hosts, mais il peut également être une source dynamique comme une base de données, un script, ou un service cloud.
* Structure :
    ** *Hôtes* : Chaque machine est listée par son nom ou son adresse IP.
    ** *Groupes* : Les nœuds peuvent être organisés en groupes pour simplifier la gestion. Cela permet d'appliquer des playbooks à des ensembles de nœuds spécifiques.
    ** *Variables* : Des variables peuvent être associées à des hôtes ou à des groupes pour configurer le comportement des playbooks.
* *Inventaires Dynamiques* : Au lieu d'un fichier statique, Ansible peut utiliser des scripts ou des plugins pour générer dynamiquement l'inventaire. Cela est particulièrement utile pour les environnements cloud où les ressources peuvent être éphémères.
* *Ciblage des Hôtes* : Lors de l'exécution d'un playbook, vous pouvez spécifier des groupes ou des hôtes individuels pour cibler spécifiquement les systèmes concernés.
--
