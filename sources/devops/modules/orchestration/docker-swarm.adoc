== Introduction à Docker Swarm

Docker Swarm est un outil d’orchestration de conteneurs conçu pour simplifier et optimiser le déploiement et la gestion d’applications à grande échelle. Il permet de regrouper plusieurs hôtes Docker, appelés “nœuds”, en un seul cluster.

// TIP : Texte original de la section pour détails complets 
[NOTE.speaker]
--
Docker Swarm facilite la coordination et la distribution des tâches entre les différents nœuds d'un cluster, ce qui est crucial pour la haute disponibilité et la mise à l'échelle automatique des applications conteneurisées.
--

=== Pourquoi Utiliser Docker Swarm ?

* Facilité d’utilisation et intégration native avec Docker.
* Haute disponibilité et mise à l’échelle automatique.
* Répartition de charge et tolérance aux pannes.
* Gestion simplifiée des secrets et des configurations.

[NOTE.speaker]
--
Docker Swarm s’intègre parfaitement avec l’écosystème Docker, offrant des fonctionnalités avancées de répartition de charge et de gestion des secrets tout en assurant la haute disponibilité des applications.
--

== Architecture de Docker Swarm

=== Structure du Cluster

Un cluster est composé de nœuds managers et workers. Les nœuds managers gèrent l’état du cluster et les nœuds workers exécutent les conteneurs.

[NOTE.speaker]
--
Les nœuds managers utilisent l’algorithme de consensus Raft pour assurer la cohérence et la fiabilité du cluster. Chaque instance d’un service est appelée une tâche, orchestrée selon les spécifications du service.
--

=== Réseau Overlay et Stockage

Docker Swarm utilise des réseaux overlay pour la communication entre conteneurs, avec des mécanismes de découverte de services intégrés.

[NOTE.speaker]
--
Les volumes dans Docker Swarm permettent la persistance des données au-delà du cycle de vie des conteneurs individuels.
--

== Prérequis pour Docker Swarm

=== Installation de Docker

Vérifiez que Docker est installé avec la commande :
```
docker --version
```

=== Configuration du Réseau

Assurez-vous que les ports requis (TCP 2377 pour la communication entre managers et TCP/UDP 7946, UDP 4789 pour la communication entre nœuds) sont ouverts et accessibles.

== Initialisation et Gestion de Docker Swarm

=== Initialisation d’un Cluster

Pour initialiser le mode Swarm, utilisez :
```
docker swarm init
```
Même sur un seul nœud, notez le token de worker pour future extension avec :
```
docker swarm join-token worker
```
Vérifiez l'état de votre cluster avec :
```
docker node ls
```

=== Comprendre les Fichiers Stack.yaml

Les fichiers `stack.yaml` sont centraux dans Swarm, servant à définir les services, réseaux, et volumes. Ils sont similaires mais adaptés pour une orchestration multi-nœuds par rapport à `docker-compose.yml`.

*Exemple de Spécification de Déploiement* :
```yaml
services:  
  mon_service:    
    image: mon_image    
    deploy:      
      replicas: 5      
      update_config:        
        parallelism: 2        
        delay: 10s
```

=== Déploiement de la Stack avec stack.yaml

Après avoir créé le `stack.yaml` :
```
docker stack deploy -c stack.yaml ma_stack
```
Consultez les services avec :
```
docker stack services ma_stack
```

== Gestion et Mise à Jour de Votre Stack

Surveillez l’état des services avec :
```
docker stack services ma_stack
```

Mettez à jour un service en ajustant le nombre de réplicas :
```
docker service update --replicas=5 ma_stack_web
```

Pour les détails des tâches :
```
docker service ps
```

== Dépannage Commun

=== Problème 1 : Services qui ne démarrent pas

* Vérifiez les logs :
  ```
  docker service logs mon_service
  ```
* Assurez-vous de la disponibilité des images et des ressources système.

=== Problème 2 : Problèmes de Réseau entre les Conteneurs

* Vérifiez la configuration réseau dans `stack.yaml`.

=== Problème 3 : Échec de l’Équilibrage de Charge

* Vérifiez l’état des services :
  ```
  docker service ls
  ```

=== Problème 4 : Mise à Jour de Service Échouée

* Consultez les logs :
  ```
  docker service logs mon_service
  ```

=== Problème 5 : Nœuds Injoignables ou Défaillants

* Vérifiez la connectivité réseau :
  ```
  docker node ls
  ```

== Nettoyage de la Stack

Pour supprimer une stack :
```
docker stack rm ma_stack
```
Nettoyez les réseaux et volumes orphelins avec :
```
docker network prune
docker volume prune
```
Supprimez les images inutilisées :
```
docker image prune -a
```
Et les conteneurs arrêtés :
```
docker container prune
```
