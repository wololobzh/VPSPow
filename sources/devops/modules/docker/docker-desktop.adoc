== Fondamentaux
// tag::deroulement[]
* Docker Desktop = interface graphique pour Docker
* à la base Docker est une CLI (Command Line Interface)
* il permet de tester, déployer et gérer des environnements conteneurisés sans interférer avec le système hôte

=== Comprendre l'utilité de Docker Desktop

* permet d'émuler les environnements de production en local
* permet une portabilité des applications sur n'importe quel système
* permet l'automatisation des flux de travail, il s'intègre dans les processus de déploiement

[NOTE.speaker]
--
Émulation d'environnements de production : Docker permet de recréer l'environnement de production sur un poste local sans avoir besoin d'une infrastructure complexe. Cela facilite les tests en amont, réduisant ainsi les risques de problèmes lors des déploiements en production.

Portabilité des applications : Les conteneurs créés via Docker fonctionnent de manière identique quel que soit l'environnement (local, cloud, serveur), garantissant que les applications se comportent de la même manière partout.

Automatisation des flux de travail : Docker Desktop s'intègre facilement dans les pipelines CI/CD, ce qui permet d'automatiser le processus de développement, de test et de déploiement.
--

=== GUI vs CLI

[cols="1,1,1"]
|===
|
| **GUI (Graphical User Interface)**
| **CLI (Command Line Interface)**

| **Avantages**
a|
* Facile et rapide à prendre en main
* Outils de monitoring visuels intégrés
* Gestion rapide en quelques clics
* Adapté aux débutants
* Paramétrage simplifié
a|
* Contrôle complet (fonctions avancées)
* Automatisation (scripting)
* Meilleure performance
* Plus rapide à utiliser pour les utilisateurs expérimentés
* Intégration aux outils de développement

| **Inconvénients**
a|
* Fonctionnalités limitées
* Consomme plus de ressources
* Moins flexible pour l'automatisation
* Plus lent pour les opérations en masse
a|
* Courbe d'apprentissage plus raide
* Aucun feedback visuel
* Risque d'erreur
* Pas recommandable pour un débutant
|===
