== Introduction

- Traefik est un reverse proxy moderne.
- Caractéristiques principales : reverse proxy, load balancing, auto-discovery.

[NOTE.speaker]
--
Traefik est un reverse proxy moderne conçu pour s'intégrer avec les orchestrateurs de conteneurs tels que Docker. Il offre des fonctionnalités avancées comme le load balancing, le support d'auto-discovery et une configuration dynamique.
--

== Concepts

* Entrypoints
* Routers
* Middlewares
* Services
* Providers

image::https://doc.traefik.io/traefik/assets/img/traefik-architecture.png[]

[NOTE.speaker]
--
Ces concepts collaborent pour permettre à Traefik de gérer efficacement le routage et le traitement des requêtes dans des environnements de conteneurs et de microservices.
--

=== Entrypoints

Les points d'entrée représentent les ports sur lesquels Traefik écoute les requêtes entrantes. Ils sont configurés pour accepter le trafic via différents protocoles comme HTTP, HTTPS, TCP, etc.

=== Routers

Les routeurs déterminent si une requête entrante doit être traitée ou non par Traefik. Ils définissent les règles de routage basées sur divers critères, tels que les en-têtes de requête, les URL, etc.

=== Middlewares

Les middlewares modifient les requêtes avant qu'elles n'atteignent le service backend. Ils peuvent être utilisés pour des tâches comme l'authentification, la gestion des en-têtes, la réécriture d'URL, etc.

=== Services

Les services représentent les applications ou microservices vers lesquels les requêtes sont dirigées après avoir été traitées par Traefik. Ils définissent comment Traefik se connecte aux applications, y compris les détails de load balancing.

=== Providers

Les providers sont des sources de configuration dynamique pour Traefik. Ils permettent de récupérer les informations de configuration à partir de divers systèmes tels que Docker, Kubernetes, fichiers statiques, etc.

== Edge Router

Traefik en tant que reverse proxy.

image::https://doc.traefik.io/traefik/assets/img/traefik-concepts-1.png[]

[NOTE.speaker]
--
Traefik agit comme un reverse proxy pour les services backend, en acheminant le trafic entrant vers les applications appropriées en fonction des règles de routage définies.
--

=== Installation de base avec Docker

https://doc.traefik.io/traefik/getting-started/configuration-overview/#the-static-configuration[Configuration statique]

```toml
[entryPoints]
  [entryPoints.web]
    address = ":80"
```

```bash
docker run -d -p 8080:8080 -p 80:80 \
    -v $PWD/traefik.toml:/etc/traefik/traefik.toml traefik
```

[NOTE.speaker]
--
Utilisez un fichier de configuration pour définir les points d'entrée et les routes. Par exemple, le fichier `traefik.toml` peut être utilisé pour configurer un point d'entrée sur le port 80.
--

== Auto-discovery avec Traefik

L'auto-discovery permet à Traefik de détecter automatiquement les nouveaux services dans votre environnement Docker.

Utilisez des labels pour configurer le routage et les règles d'accès.

image::https://doc.traefik.io/traefik/assets/img/traefik-concepts-2.png[]

=== Utilisation avec Docker Compose

https://doc.traefik.io/traefik/getting-started/quick-start/[Quick Start]


```yaml
services:
    reverse-proxy:
        image: traefik
        command: --api.insecure=true --providers.docker
        ports:
        - "80:80"
        - "8080:8080"
        volumes:
        - /var/run/docker.sock:/var/run/docker.sock

    whoami:
        image: traefik/whoami
        labels:
        - "traefik.http.routers.whoami.rule=Host(`whoami.docker.localhost`)"
```

[NOTE.speaker]
--
Le service whoami sera accessible avec l'url `http://whoami.docker.localhost`. Traefik détecte automatiquement le service et configure les règles de routage en fonction des labels définis.
--

* Aller sur `http://whoami2.docker.localhost`
