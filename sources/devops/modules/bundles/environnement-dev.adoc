== Introduction

Ce module explore les différences cruciales entre les environnements de développement et de production, l'importance des tests unitaires, ainsi que les considérations importantes pour le déploiement d'applications web, avec un focus particulier sur les projets Svelte.

== Différence entre développement et production

=== Variables d'environnement

Les variables d'environnement sont essentielles pour distinguer et configurer les environnements de développement et de production.

.Exemple de variables en développement
[source,bash]
----
NODE_ENV=development
API_URL=http://localhost:3000/api
DEBUG=true
----

.Exemple de variables en production
[source,bash]
----
NODE_ENV=production
API_URL=https://api.monapp.com
DEBUG=false
----

[TIP]
--
Utilisez des fichiers `.env` pour gérer vos variables d'environnement et assurez-vous de ne pas les committer dans votre dépôt Git.
--

=== Optimisation des performances

[cols="1,1,2", options="header"]
|===
|Aspect |Développement |Production
|Bundling |Minimal ou inexistant |Optimisé et minifié
|Sourcemaps |Détaillées |Limitées ou absentes
|Logging |Verbeux |Minimal
|Caching |Désactivé |Activé et optimisé
|===

== Configuration des chemins d'accès

=== Importance des chemins relatifs

* Assure le fonctionnement correct de l'application, indépendamment du répertoire de base du serveur
* Crucial pour les déploiements sur des plateformes comme GitHub Pages

=== Bonnes pratiques

. Utilisez des chemins relatifs dans vos fichiers HTML et JavaScript
. Configurez correctement la `base` dans votre configuration Vite pour Svelte
. Utilisez des imports dynamiques pour les ressources dans Svelte

.Configuration Vite pour Svelte
[source,javascript]
----
// vite.config.js
import { defineConfig } from 'vite'
import { svelte } from '@sveltejs/vite-plugin-svelte'

export default defineConfig({
  plugins: [svelte()],
  base: '/mon-projet/' // Pour GitHub Pages
})
----

== Tests Unitaires

=== Importance des tests unitaires

Les tests unitaires sont cruciaux pour :

* Assurer la qualité du code
* Détecter les régressions
* Faciliter la maintenance et les refactorisations
* Documenter le comportement attendu du code

=== Configuration des tests pour Svelte

Pour Svelte, nous utiliserons Vitest comme framework de test.

.Installation des dépendances
[source,bash]
----
npm install --save-dev vitest @testing-library/svelte jsdom
----

.Configuration de Vitest
[source,javascript]
----
// vite.config.js
import { defineConfig } from 'vite'
import { svelte } from '@sveltejs/vite-plugin-svelte'

export default defineConfig({
  plugins: [svelte()],
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: ['./src/setupTests.js']
  }
})
----

=== Écriture de tests unitaires

.Exemple de test pour un composant Svelte
[source,javascript]
----
// Counter.test.js
import { render, fireEvent } from '@testing-library/svelte'
import Counter from './Counter.svelte'

test('increments count when button is clicked', async () => {
  const { getByText } = render(Counter)
  const button = getByText('Count is 0')
  
  await fireEvent.click(button)
  
  expect(button.textContent).toBe('Count is 1')
})
----

=== Exécution des tests

Ajoutez un script dans votre `package.json` pour exécuter les tests :

[source,json]
----
{
  "scripts": {
    "test": "vitest"
  }
}
----

Exécutez les tests avec :

[source,bash]
----
npm run test
----

== Création d'une version de production

=== Configuration du projet Svelte pour la production

. Ajustez les variables d'environnement
. Configurez le fichier `svelte.config.js`
. Créez un script de build dans `package.json`

=== Configuration Svelte pour la production
[source,javascript]
----
// svelte.config.js
import adapter from '@sveltejs/adapter-static';

const config = {
  kit: {
    adapter: adapter({
      pages: 'build',
      assets: 'build',
      fallback: 'index.html',
      precompress: false
    }),
    prerender: {
      default: true
    }
  }
};

export default config;
----

=== Processus de build

. Nettoyez le répertoire de build existant
. Exécutez le script de build
. Vérifiez le contenu du répertoire `build`

[source,bash]
----
npm run build
ls -R build
----

== Conclusion

// tag::conclusion[]
* La compréhension des différences entre développement et production est cruciale pour un déploiement réussi
* La gestion appropriée des variables d'environnement est essentielle pour la sécurité et la flexibilité
* Les tests unitaires sont fondamentaux pour assurer la qualité et la maintenabilité du code
* L'optimisation des performances doit être une priorité pour la version de production
* La configuration correcte des chemins d'accès est vitale pour le bon fonctionnement de l'application déployée
* Un processus de build, de test et de déploiement bien défini améliore significativement la qualité et la fiabilité du projet
* La pratique régulière du déploiement, des tests et de l'optimisation est nécessaire pour maîtriser ces compétences DevOps
// end::conclusion[]
