== Introduction

Scripts exécutés à divers moments du cycle de vie des actions Git.

* Utilité : Automatisation de tâches répétitives et amélioration de la qualité du code
* Types de hooks :
  ** Côté client (pré-commit, post-merge, etc.)
  ** Côté serveur (pré-receive, post-receive, etc.)

[NOTE.speaker]
--
Les hooks Git sont des scripts que vous pouvez exécuter automatiquement à différents points du cycle de vie d'une action Git. Ils sont utiles pour automatiser des tâches telles que les tests, le formatage du code, ou la génération de documentation. 

Il existe des hooks côté client, qui s'exécutent sur votre machine locale, et des hooks côté serveur, qui s'exécutent sur le serveur distant.
--

== Utilisation des hooks côté client

* *prepare-commit-msg* : avant l'ouverture de l'éditeur de message de commit, une fois le message préparé par défaut. Peut être utilisé pour modifier le message par défaut.
* *commit-msg* : après l'écriture du message de commit. Peut être utilisé pour valider le message de commit.
* *pre-commit* : avant qu'un commit ne soit validé. Utilisé pour vérifier le code ou lancer des tests.
* *post-commit* : après qu'un commit a été créé. Peut être utilisé pour des notifications ou des actions post-commit.
* *pre-rebase* : avant qu'une opération de rebase ne commence. Peut être utilisé pour vérifier l'état du dépôt.
* *post-rewrite* : après des réécritures de l'historique, comme avec git commit --amend et git rebase.
* *post-merge* : après qu'un git merge a été exécuté avec succès. Peut être utilisé pour des actions de nettoyage ou de notification.
* *pre-push* : avant qu'un git push ne soit exécuté. Peut être utilisé pour vérifier l'état du dépôt avant de pousser.
* *pre-applypatch* : avant qu'un patch ne soit appliqué avec git am.
* *applypatch-msg* : après qu'un patch a été appliqué, mais avant que le message de commit ne soit rédigé.
* *post-applypatch* : après qu'un patch a été appliqué avec git am.

== Démonstration

Configurer un hook `pre-commit` pour lancer des tests unitaires

[NOTE.speaker]
--
Nous allons configurer un hook `pre-commit` pour lancer des tests unitaires via Vitest.

* Aller dans le répertoire `.git/hooks` de votre dépôt
* Renommer `pre-commit.sample` en `pre-commit`
* Éditer le fichier `pre-commit` pour inclure la commande de test
* Exemple de commande : `npm run test`
* Sauvegarder le fichier et donner les permissions d'exécution : `chmod +x .git/hooks/pre-commit`
* Faire un commit pour voir le hook en action
--

== Conclusion

// tag::conclusion[]
* Les hooks Git permettent d'automatiser des tâches et d'améliorer la qualité du code
* Le hook `pre-commit` est idéal pour exécuter des tests avant chaque commit
* Le hook `pre-push` peut garantir que le code se build correctement avant d'être poussé
