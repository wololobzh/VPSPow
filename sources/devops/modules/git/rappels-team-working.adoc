== Outils pour la collaboration

* Git : Outil essentiel pour le travail collaboratif
* GitHub : Plateforme facilitant la gestion de projets en équipe
* Rôles et permissions : Organisation des équipes sur GitHub

[NOTE.speaker]
--
Git permet de gérer efficacement le code source en équipe, facilitant la collaboration et le suivi des modifications. GitHub ajoute des fonctionnalités pour gérer les projets, les équipes, et les revues de code.
--

== Process

. Initialisation d'un dépôt sur Github (ou local puis ajout du remote)
. Définition des rôles et des permissions
. Ajout des collaborateurs au projet
. Utilisation des branches pour isoler les fonctionnalités
. Configuration de l'environnement de développement local dans une branche
. Création de pull requests pour fusionner les branches
. Optionnel : Création d'un github project pour suivre les tâches

// tag::demo[]
== Démonstration 1

Aperçu de la configuration d'une organisation GitHub.

[NOTE.speaker]
--
Dans le cadre d'une entreprise, il est utile d'avoir une organisation GitHub. Prendre l'exemple de l'orga Devops pour montrer les teams et les permissions.

* Montrer les teams et la hiérarchie
* Montrer les personnes et les types (owner, member, outside collaborator)
* Montrer les assignements de rôles au niveau de l'orga
** Settings > Organization roles > Roles assignements > Teams
** PNO est All-repository admin, les autres sont All-repository read
* Montrer les base permissions dans Member privileges
** Read veut dire qu'en faisant partie de l'orga, on a accès à tous les repos en lecture
** On pourrait mettre en No permissions
* Montrer les rulesets dans Repository
** Les branches main sont par défaut protégées
** Le PNO à les droits de bypasser les protections

Au niveau d'un repo de l'orga:

* Montrer qui a accès dnas Settings > Collaborators and teams 

Les repo étant par défaut en lecture pour le pôle RUN, on peut préciser sur certains que le pôle à des droits d'écriture. La protection de la branche main reste en place.
--

== Démonstration 2

Initialisation d'un projet en suivant les bonnes pratiques.

[NOTE.speaker]
--
A partir de l'orga Github de la promo :

* Créer un dépôt S09-Demo, par défaut ce repo n'est pas visible des apprenants
* Le partager à toute la promo dans Settings > Collaborators and teams > Add teams
* Ajouter une protection sur la branche main
* Cloner le repo en local
* Mettre en place un environnement de développement local avec Docker Compose
** Un seul service node alpine avec un volume pour le code
** Utiliser un template vite svelte ts
* Essayer de pusher sur la branche main, le push est refusé
* Créer une branche et pusher dessus
* Créer une pull request pour merger la branche
** Ajouter un apprenant comme reviewer
* Fusionner la pull request
* Supprimer la branche
--

== Démonstration 3

Création d'un projet GitHub pour suivre les tâches.

[NOTE.speaker]
--
* Créer un projet dans le repo S09-Demo
* Créer une tâche "Conversion de devises" dans la colonne "To do"
* Créer une tahce "Ajout de tests" dans la colonne "To do"
* Déplacer la tâche "Conversion de devises" dans la colonne "In progress"
* Convertir la tâche en issue
* Définir les différents champs et une description
* Utiliser le bouton "Create a branch"

Une issue est prête pour être traitée, avec une branche associée.
--
