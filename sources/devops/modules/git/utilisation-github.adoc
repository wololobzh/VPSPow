== Introduction

Après avoir découvert GitHub Projects et Kanban, nous allons approfondir deux fonctionnalités essentielles de GitHub pour la collaboration : les Issues et les Pull Requests.

== Les Issues GitHub

image::https://media.tenor.com/_ZCQz_Kub5EAAAAC/afas-afassoftware.gif[]

=== Qu'est-ce qu'une Issue ?

Une Issue sur GitHub est un outil polyvalent utilisé pour :

- Signaler des bugs
- Proposer des améliorations
- Planifier de nouvelles fonctionnalités
- Poser des questions
- Organiser des tâches

=== Création d'une Issue

1. Naviguez vers l'onglet "Issues" du dépôt
2. Cliquez sur "New issue"
3. Remplissez le titre et la description
4. Ajoutez des labels, des assignés, et des jalons si nécessaire
5. Cliquez sur "Submit new issue"

[NOTE.speaker]
--
Démontrez la création d'une Issue en direct, en expliquant l'importance de chaque champ.
--

=== Bonnes pratiques pour les Issues

- Utilisez des titres clairs et descriptifs
- Fournissez des détails suffisants dans la description
- Utilisez des listes à puces ou numérotées pour les étapes ou les critères
- Ajoutez des captures d'écran ou des GIFs si pertinent
- Utilisez les mentions (@username) pour attirer l'attention de personnes spécifiques

== Les Pull Requests (PR)

=== Qu'est-ce qu'une Pull Request ?

Une Pull Request est une proposition de changements à apporter au code source. Elle permet :

- De présenter des modifications pour revue avant fusion
- De discuter et d'itérer sur les changements proposés
- D'assurer la qualité du code par la revue par les pairs

=== Workflow typique d'une Pull Request

1. Créez une nouvelle branche pour vos modifications
2. Effectuez vos changements et committez-les
3. Poussez la branche vers GitHub
4. Ouvrez une Pull Request depuis cette branche
5. Discutez et itérez sur les changements
6. Fusionnez la PR une fois approuvée

=== Création d'une Pull Request

1. Allez sur la page principale du dépôt
2. Cliquez sur "Pull requests", puis sur "New pull request"
3. Sélectionnez la branche contenant vos modifications
4. Remplissez le titre et la description de la PR
5. Cliquez sur "Create pull request"

[NOTE.speaker]
--
Montrez le processus complet de création d'une PR, de la création de la branche à la soumission de la PR.
--

=== Bonnes pratiques pour les Pull Requests

- Gardez les PR de taille raisonnable (petites et ciblées)
- Utilisez des titres clairs et descriptifs
- Fournissez une description détaillée des changements
- Liez la PR aux Issues correspondantes
- Répondez rapidement aux commentaires et aux demandes de modifications

== Intégration avec GitHub Projects

=== Lier les Issues et les PR au tableau Kanban

1. Ouvrez votre projet GitHub
2. Cliquez sur "+ Add item" dans une colonne
3. Recherchez et sélectionnez l'Issue ou la PR à ajouter

=== Automatisation du flux de travail

- Configurez des règles pour déplacer automatiquement les Issues/PR entre les colonnes
- Exemple : Déplacer une Issue dans "In Progress" lorsqu'une PR liée est ouverte

== Revue de code efficace

1. Examinez le code ligne par ligne
2. Laissez des commentaires constructifs
3. Suggérez des améliorations si nécessaire
4. Approuvez la PR ou demandez des modifications

[NOTE.speaker]
--
Démontrez une revue de code en direct, en soulignant l'importance d'un feedback constructif et respectueux.
--

== Exercice pratique : Collaboration sur un projet open source

Vous allez simuler une collaboration sur un projet open source fictif.

=== Étape 1 : Préparation

1. Créez un nouveau dépôt GitHub nommé "awesome-collab-project"
2. Initialisez-le avec un README.md et un fichier CONTRIBUTING.md basique
3. Créez un projet Kanban associé à ce dépôt

=== Étape 2 : Création d'Issues

1. Créez 3 Issues :
   - "Ajouter une page d'accueil"
   - "Implémenter une fonctionnalité de recherche"
   - "Optimiser les performances de la base de données"
2. Ajoutez des descriptions détaillées et des labels appropriés
3. Ajoutez ces Issues à votre tableau Kanban

=== Étape 3 : Travail sur une fonctionnalité

1. Choisissez une des Issues créées
2. Créez une nouvelle branche pour travailler dessus
3. Faites quelques modifications dans le code (vous pouvez simuler cela en modifiant le README.md)
4. Committez vos changements et poussez la branche

=== Étape 4 : Création d'une Pull Request

1. Ouvrez une Pull Request pour votre branche
2. Liez la PR à l'Issue correspondante
3. Remplissez une description détaillée de vos changements

=== Étape 5 : Revue de code

1. Examinez votre propre PR comme si vous étiez un autre contributeur
2. Laissez au moins 2 commentaires ou suggestions d'amélioration
3. Apportez les modifications suggérées dans un nouveau commit

=== Étape 6 : Finalisation

1. Approuvez la PR (simulez cela en laissant un commentaire d'approbation)
2. Fusionnez la PR dans la branche principale
3. Fermez l'Issue correspondante
4. Mettez à jour votre tableau Kanban pour refléter ces changements

=== Étape 7 : Réflexion

Répondez aux questions suivantes :

1. Comment l'utilisation combinée des Issues, des PR et du tableau Kanban a-t-elle amélioré la visibilité et la gestion du travail ?
2. Quels avantages voyez-vous à utiliser des branches séparées et des PR pour chaque fonctionnalité ?
3. Comment ce processus pourrait-il être amélioré pour une équipe travaillant sur un projet plus grand ?
