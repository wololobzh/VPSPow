== Qu'est-ce qu'un test de charge ?

* Pour évaluer si une application peut gérer un trafic élevé, au plus proche des conditions réelles
* Détecte les goulets d'étranglement, les problèmes de performance et les limites de capacité de l'infrastructure
* Permet de déterminer le seuil à partir duquel l'application est ralentie
* Utile pour cibler les améliorations à apporter sur l'application

== Les métriques importantes

* **L'indice Apdex** (Application Performance Index) : évalue la satisfaction des utilisateurs par rapport à la performance d'une application
* **Le temps de réponse** : on analyse les temps minimum / maximum, la moyenne, la médiane, les 95e et 99e percentiles
* **Le taux d'erreur** : pourcentage de requêtes qui ont échoué ou généré des erreurs
* **Le débit utilisé** : poids en octets de données qui est consommé

[NOTE.speaker]
--
* 🔗 https://www.lebigdata.fr/apdex-definition[Plus d'infos sur Apdex^]
* **95e et 99e percentiles** : représente l'expérience de 95% / 99% des utilisateurs et permet de donner une idée de la performance pour la grande majorité des utilisateurs.
--

== En pratique avec Artillery !

* Outil Open source, rapide à mettre en place
* Permet d'effectuer des tests de charge HTTP et WebSockets
* Fournit des rapports détaillés
* Possibilité d'étendre les fonctionnalités avec des plugins

🔗 https://www.artillery.io/docs[Documentation d'Artillery]

=== Lancer un test

* Installer Artillery en global (`npm i -g artillery@latest`)
* Créer un fichier de config `.yml` (on voit un exemple juste après)
* Lancer la commande `npx artillery run config.yml`
* Le test peut durer plusieurs minutes, c'est l'heure d'aller se faire un café ☕

=== Exemple de configuration

```yaml
config:
  # L'application à tester
  target: http://localhost:3000
  # On peut découper le test en plusieurs phases
  phases:
      # Durant 60 secondes, augmente graduellement
      # le nombre d'utilisateurs de 1 à 5 par seconde
    - duration: 60
      arrivalRate: 1
      rampTo: 5
      name: Warm up phase
    - duration: 60
      arrivalRate: 5
      rampTo: 10
      name: Ramp up load
    - duration: 30
      arrivalRate: 10
      rampTo: 30
      name: Spike phase
  plugins:
    # Permet d'établir des seuils de performance
    ensure: {}
    # Plugin pour obtenir le score Apdex
    apdex: {}
    # Permet de collecter les métriques pour chaque route testée
    metrics-by-endpoint: {}
  apdex:
    # Seuil en milliseconde, au delà
    # on considèrera que ce n'est pas satisfaisant
    threshold: 100
  ensure:
      thresholds:
          # Seuil en ms pour les percentiles 99e et 95e
        - http.response_time.p99: 100
        - http.response_time.p95: 75

# Définition des scénarios de test
scenarios:
  - flow:
      - loop:
        - get:
            url: "/dino"
        - get:
            url: "/pony"
        - get:
            url: "/armadillo"
        # Nombre d'itérations de la boucle
        count: 100
```
