== Introduction

* Définition : ils vérifient le bon fonctionnement d'un morceau de code
* Importance des tests dans le cycle de développement
* Identification des erreurs rapidement

[NOTE.speaker]
--
Les tests unitaires sont des tests automatisés qui vérifient le bon fonctionnement d'une unité de code, généralement une fonction ou une méthode. Ils sont cruciaux pour s'assurer que chaque partie du code fonctionne comme prévu. 

Les tests permettent de détecter les erreurs tôt dans le processus de développement, ce qui réduit le coût des corrections.
--

== Avantages

* Réduction des bugs
* Facilite les changements de code
* Documentation vivante du comportement attendu

[NOTE.speaker]
--
Les tests unitaires aident à réduire les bugs en vérifiant chaque unité de code individuellement. Ils facilitent également les modifications du code, car les développeurs peuvent être certains que les changements n'introduisent pas de nouvelles erreurs. 

Les tests servent de documentation, montrant comment chaque unité de code doit se comporter.
--

== Cas d'usage

* Validation de fonctions critiques
* Refactoring de code en toute confiance
* Intégration dans les pipelines CI/CD

[NOTE.speaker]
--
Les tests unitaires sont particulièrement utiles pour valider les fonctions critiques de votre application. Ils permettent également de refactorer le code en toute confiance, car vous pouvez vérifier que les modifications n'ont pas cassé le comportement existant. 

Les tests peuvent être intégrés dans les pipelines CI/CD pour une validation continue.
--

== Outils de test web front-end

* https://vitest.dev/[Vitest] dans le cadre d'un projet avec Vite
* Jest
* Mocha

[NOTE.speaker]
--
Vitest est un outil moderne pour les tests unitaires qui s'intègre bien avec les projets Front. Il offre des fonctionnalités similaires à Jest et Mocha, mais avec une approche plus légère et une intégration facile avec Vite. 

Jest est populaire pour sa richesse fonctionnelle, tandis que Mocha est apprécié pour sa flexibilité.

Chaque langage de programmation a ses propres outils de test unitaire, comme JUnit pour Java ou NUnit pour C#.
--

== Autres types de tests

* Tests d'intégration
* Tests fonctionnels (end-to-end)
* Tests de performance ou de charge

[NOTE.speaker]
--
Les tests unitaires sont un type de test parmi d'autres. Les tests d'intégration vérifient le bon fonctionnement des composants ensemble, tandis que les tests fonctionnels simulent le comportement de l'utilisateur.
--

== Démonstration 1

Création d'une fonction de conversion de devise (dollar vers euro)

// tag::demo[]
[NOTE.speaker]
--
Nous allons créer une fonction simple qui convertit des dollars en euros. Cette fonction prendra un montant en dollars et le convertira en euros en utilisant un taux de conversion fixe.

Nous n'intégrerons pas cette fonction dans le DOM pour simplifier l'exemple.

* Créer un fichier nommé conversion.ts
* Définir une fonction convertDollarToEuro
* Utiliser un taux de conversion fixe, par exemple 1 dollar = 0.85 euro
* Retourner le montant converti en euros
* Commit et push sur la branche
* PR + merge
--
// end::demo[]

== Démonstration 2

Test de la fonction de conversion avec Vitest

// tag::demo[]
[NOTE.speaker]
--
Nous allons maintenant tester notre fonction de conversion de devise en utilisant Vitest. Nous vérifierons si la fonction retourne les résultats attendus pour différents montants, dans l'idéal des cas limites.

* Installer Vitest dans votre projet

```bash
npm install -D vitest
```

.package.json
```json
{
  "scripts": {
    "test": "vitest"
  }
}
```

* Créer un fichier de test nommé conversion.test.js
* Importer la fonction convertDollarToEuro
* Écrire plusieurs cas de test pour vérifier les résultats
* Exécuter les tests avec Vitest et vérifier les résultats
* Commit et push sur la branche
* PR + merge

```bash
npm run test
```
--
