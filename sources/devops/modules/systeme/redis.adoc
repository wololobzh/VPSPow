== Introduction

https://redis.io/[Redis] est une base de données open-source extrêmement rapide et légère.

.Principaux cas d’usage : 
* caching
* sessions
* file d’attente

[NOTE.speaker]
--
* La mise en cache mémoire permet d'accélérer les applications
* Les sessions utilisent Redis pour stocker les données propre à chaque utilisateur de manière efficace
* Les files d'attente permettent de gérer les tâches asynchrones
--

=== Fonctionnement

Redis est une base de données NoSQL en mémoire, stockant les données en clé-valeur.

* Stockage des données en mémoire vive
* Utilisation de structures de données complexes
* Haute performance et faible latence

```redis
SET ma_cle "valeur"
GET ma_cle
```

[NOTE.speaker]
--
Le stockage clé-valeur de Redis permet de stocker des données de manière simple et efficace. Il n'est pas conçu pour remplacer les bases de données relationnelles, mais pour des cas d'usage spécifiques.

Le stockage en mémoire permet d'obtenir des performances très élevées, mais contraint la taille des données stockées.

Les coockies dans les navigateurs sont un exemple de stockage clé-valeur.
--

== Installation de Redis

* Installation sur Linux (Debian/Ubuntu) : via `apt`
* Installation sur macOS : via `brew`
* Installation sur Windows : via WSL ou Docker

[NOTE.speaker]
--
Selon l'environnement, l'installation de Redis peut se faire de manière très simple avec les gestionnaires de paquets standards.

Avec des stacks modernes, Redis est souvent utilisé dans des conteneurs Docker pour faciliter le déploiement.
--

.Installation sur Ubuntu/Debian https://redis.io/docs/latest/operate/oss_and_stack/install/install-redis/install-redis-on-linux/[Documentation officielle]
```bash
sudo apt-get install lsb-release curl gpg
curl -fsSL https://packages.redis.io/gpg | sudo gpg --dearmor -o /usr/share/keyrings/redis-archive-keyring.gpg
sudo chmod 644 /usr/share/keyrings/redis-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/redis-archive-keyring.gpg] https://packages.redis.io/deb $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/redis.list
sudo apt-get update
sudo apt-get install redis
```

[NOTE.speaker]
--
Etape par étape :

. Installation des dépendances
. Ajout de la clé GPG
. Application des droits sur la clé
. Ajout du dépôt Redis
. Mise à jour des paquets
. Installation de Redis
--

=== Démarrage et gestion du service Redis

* Commandes pour démarrer/arrêter Redis
* Vérification de l'état du service

[NOTE.speaker]
--
Redis démarre automatiquement après installation, mais vous pouvez utiliser `systemctl` pour gérer le service sur les systèmes Linux.


== Configuration de Redis

https://redis.io/docs/latest/operate/oss_and_stack/management/config/[Documentation officielle]

* Fichier de configuration `redis.conf`
* Paramètres importants : mémoire, connexions, persistance
* Configuration pour la persistance des données (RDB et AOF)

Toutes les possibilités de configuration : https://redis.io/docs/latest/operate/oss_and_stack/management/config-file/[Redis configuration example]

[NOTE.speaker]
--
Le fichier `redis.conf` contient tous les paramètres essentiels pour ajuster Redis à votre environnement de production, comme la gestion de la mémoire et les options de persistance des données.
--

=== Configuration de la mémoire

* Limiter la mémoire avec `maxmemory`
* Définir des politiques d'éviction de données (`maxmemory-policy`)

.redis.conf
```bash
maxmemory 256mb
maxmemory-policy allkeys-lru
```

[NOTE.speaker]
--
Il est essentiel de limiter la mémoire de Redis, surtout en production, et de définir une politique d'éviction pour garantir que les données moins fréquemment utilisées soient supprimées en cas de besoin.
--

=== Configuration des connexions

* Limiter le nombre de connexions simultanées avec `maxclients`
* Configurer les timeouts de connexion

.redis.conf
```bash
maxclients 1000
timeout 300
```

[NOTE.speaker]
--
La configuration des connexions est importante pour éviter les attaques de type déni de service et garantir que Redis reste disponible pour les clients.
--

=== Configuration de la persistance

* Sauvegarde des données avec RDB (`save`) et AOF (`appendonly`)
* Configuration des fréquences de sauvegarde et de la réécriture des logs

Plus d'informations : https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/[Redis Persistence]

.redis.conf
```bash
save 900 1
appendonly yes
appendfsync everysec
```

[NOTE.speaker]
--
La persistance des données est essentielle pour garantir la disponibilité des données en cas de panne. Redis propose deux modes de persistance : RDB pour les sauvegardes complètes et AOF pour les logs d'opérations.
--

== Utilisation de Redis

* Commandes Redis de base : `SET`, `GET`, `DEL`, `EXPIRE`
* Manipulation des types de données : chaînes, listes, ensembles
* Utilisation de Redis en tant que cache avec expiration des clés

[NOTE.speaker]
--
Redis est une base de données clé-valeur très flexible, permettant de stocker des chaînes, des listes et des ensembles. L'utilisation de l'expiration des clés permet de mettre en place un cache efficace.
--

```bash
# Commandes de base
SET mykey "valeur"
GET mykey
EXPIRE mykey 60  # Expire après 60 secondes
DEL mykey
```

=== Commandes de gestion des types de données

* Utilisation des listes : `LPUSH`, `LRANGE`
* Gestion des ensembles : `SADD`, `SMEMBERS`

[NOTE.speaker]
--
Redis supporte différents types de données, comme les listes pour les files d'attente et les ensembles pour des collections uniques. Ces fonctionnalités permettent de résoudre plusieurs cas d'usage comme la gestion de sessions.
--

```bash
# Liste
LPUSH ma_liste "élément1"
LPUSH ma_liste "élément2"
LRANGE ma_liste 0 -1  # Récupère tous les éléments de la liste

# Ensemble
SADD mon_ensemble "élément"
SMEMBERS mon_ensemble
```
